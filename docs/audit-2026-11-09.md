# 项目检查与优化记录 · 2026-11-09

launchbay 是家庭局域网内的独立档案书签导航台。本次按少量家庭成员、单服务进程、文件存储的使用方式检查，保持标准库零依赖与现有权限边界。

检查覆盖启动与停机、路由和契约、PIN 与令牌、书签批量写入、导入与备份恢复、文件及快照、历史记录、图标抓取、浏览器交互、扩展通知和部署配置。深查重点是凭证判断与可能损坏、覆盖或丢失数据的通路。

## 已修复

| 优先级 | 问题与复现场景 | 修复与验证 |
|---|---|---|
| P1 | PIN 是 `0000` 时，空字符串、非数字和长度错误的输入被替换为 `0000` 后竟然通过校验。 | 保留格式是否合法的结果，完成哈希比较后同时要求格式有效。新增空值、全角数字、字母及长度边界回归测试，正确的 `0000` 仍可登录。 |
| P1 | 浏览器书签导入在锁外确认档案为空，提交时没有核对版本。复现中 12 个同时发起的导入全部写入，违反只导入空档案的契约。备份恢复还会移除检查时的空组，删除其间新加入的书签。 | 两条通路均携带检查时的 rev，在现有档案锁内核对后才提交。恢复冲突返回 409、`rev-conflict` 和 `currentRev`，并停止设置写入；页面也显示冲突。旧空组与并发写入回归测试、12 路并发导入和恢复测试通过，连续验证 20 轮。 |
| P1 | CLI 的响应读取器静默截断超过 4 MiB 的响应。5 MiB 备份只落下 4 MiB，命令仍返回成功，生成无法解析的 JSON。 | 完整读取本机服务的响应。新增 CLI 导出回归测试，逐字节比对超过 4 MiB 的备份。 |
| P2 | JSON 解码只读第一个顶层值，会接受合法对象后面的第二个对象或乱码；磁盘文件与备份还会把非法 UTF-8 静默替换为替代字符。 | `store.DecodeJSON` 统一要求合法 UTF-8、一个完整顶层值并拒绝未知字段。请求、备份和档案读取复用它。异常请求不写盘，损坏档案按 `ErrCorrupt` 处理，旧 `admin` 字段的升级兼容保留。 |
| P2 | 停机时关闭监听器后，主函数先于 `Shutdown` 返回，在途请求可能被进程退出打断。 | 主流程等待停机完成。真实 HTTP 回归测试让请求保持执行，触发停机后确认服务仍等待，并在释放请求后收到完整响应再退出。 |
| P2 | 删除档案只删除 `profiles/<id>/`，没有删除单独存放的 `backgrounds/<id>/`，私有背景图片继续留在磁盘。 | 在同一档案锁内显式清理它的背景目录；背景清理失败时保留档案目录以便重试。回归测试同时确认另一个档案的背景保留。 |
| P2 | 只携带有效管理员 cookie 调用恢复接口时返回 401，误报为缺少凭证；部分成功响应把 `settings` / `warnings` 写成 `null`。 | 恢复入口复用统一鉴权失败判据，管理员 cookie 得到 403；空结果集合统一为 `[]`。新增接口回归测试。 |
| P2 | 零值管理员令牌能接受用空密钥计算出的已知 HMAC cookie。正常服务启动已有非空密钥检查，但依赖装配缺失时鉴权没有自行拒绝。 | cookie 比较在管理员密钥为空时直接拒绝，补充零值令牌回归测试；没有把此问题误判为正常配置服务的管理员绕过。 |
| P2 | 扩展调用不存在的 `chrome.notifications.notify`，错误通知始终进入控制台兜底；点击去向只放在内存里，后台 worker 重启后丢失。 | 改用 `chrome.notifications.create('lb-fail', {type: 'basic', ...})`，点击去向保存到现有本地存储。一次性 Node VM 检查验证通知参数及 worker 重建后的页面/设置跳转，没有新增扩展 CI 门禁。接口依据见 [Chrome 官方文档](https://developer.chrome.com/docs/extensions/reference/api/notifications#method-create)。 |
| 优化 | 历史查询即便只请求最近几条，也把所有匹配记录保留到读取结束后再截取。 | 改成最多保留 `limit` 条记录的环形缓冲区，保留按档案过滤、最新在前、长行和坏行处理。内存中保留的记录数量从全部匹配记录降至请求条数；读取仍需扫描整个文件，不宣称读取时间变为常数。 |

恢复的新增 409 响应与 JSON 读取规则已同步到 `AGENTS.md` / `openapi.json`。

## 后续界面与使用体验调整

用户确认后落实了五项建议，并完成触屏适配：

- 拖入链接时以实际落点分组为准，自动分组建议不再覆盖用户选择；空白落点仍使用第一组。
- 空档案正文直接提供“添加第一个书签”与浏览器导入入口。添加复用既有浮层；零 JS 保留导入入口。
- 同步精简中英文引导和设置说明，改用“页面名称”“卡片副标题”等标签，纠正当前标签页“离开了回不来”的说法。
- 按桌面/触屏分别显示可关闭的操作提示。关闭状态保存在本机浏览器中，并按档案区分。
- 标签改为弱底色与透明描边，保留文字颜色、现有布局和触控尺寸。
- 窄屏触屏浮层跟随 visualViewport，键盘打开时可滚动到保存按钮；长按松手产生的点击不再取消第一条选中项。

新增的界面验收覆盖提示关闭后重载、冲突的自动分组建议、空档案入口、触屏长按松手及滚动取消、缩短可见高度后的保存按钮可达性。已检查深浅主题、桌面和手机尺寸截图。手机部分使用浏览器触屏与键盘占用空间模拟，仍不替代真实 iOS/Android 验收。应用 JS/CSS 的指纹已同步到两份契约。

本轮全量 Go 测试、vet、格式与差异检查通过；完整界面验收通过 80 步交互（原有 75 步与新增 5 项）及 3 项 Service Worker 测试。没有提交或部署。
