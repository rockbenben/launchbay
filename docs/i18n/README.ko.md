외우기 힘든 주소들을 한 페이지에 모아두세요: NAS 관리자 패널, 공유기 설정, 사내 인트라넷, 모니터링 대시보드. 브라우저 홈페이지로 지정하면, **클릭 한 번으로 즉시 열리며 로딩 지연이 없습니다.**

홈 NAS, 라즈베리 파이, 소프트 라우터, 사내 네트워크의 서버 등 내 기기에서 직접 구동되므로 북마크가 다른 사람의 서버를 거치지 않습니다.

## 왜 launchbay인가

이러한 도구들은 주로 네 가지에서 차이가 납니다: 데이터가 누구의 서버에 저장되는지, 가족 구성원이 어떻게 나누어 쓰는지, 오프라인에서도 작동하는지, 드래그로 정리할 수 있는지.

| 비교 항목 | 브라우저 기본 북마크 | 클라우드 북마크 서비스 | launchbay |
|---|---|---|---|
| 데이터 저장 위치 | 브라우저 프로필 폴더 (계정 연동) | 업체의 서버 | **내 기기** |
| 1인 1계정 분리 | 브라우저 다중 프로필 전환 | 계정별 분리 | **각자 1개씩, 서버에서 분리** |
| 오프라인 동작 | 로컬만 동작 | 동작 불가 | **캐시 + 오프라인 큐** |
| 드래그로 정리 | 폴더 트리 (단일 페이지 레이아웃 아님) | 대부분 미지원 | **드롭하여 저장, 드래그하여 순서 변경** |
| 제3자 열람 가능 여부 | 브라우저 계정 | 업체 | **앱을 통한 조회 경로 없음** |

계정 없음, 제3자 스크립트 없음, 원격 측정(telemetry) 없음. 외부 요청은 북마크 추가 시 대상 페이지(제목 확인)와 favicon을 단 한 번 가져오는 것이 전부입니다. 아이콘 가져오기에 실패한 사이트는 24시간 동안 재시도하지 않습니다.

**혼자서만 쓴다면 브라우저의 기본 북마크 페이지로도 충분할 수 있습니다.** launchbay가 제공하는 세 가지 핵심 가치는 다음과 같습니다:

- **열 때 기다리지 않습니다.** 페이지가 서버 사이드에서 렌더링되므로 스크립트가 실행되기 전에 HTML에 북마크와 아이콘이 이미 포함되어 있습니다. LAN 환경에서 첫 페인트 LCP < 300ms를 목표로 합니다 (실제 NAS 기기에서의 콜드 스타트는 아직 측정되지 않음. [제한 사항](#제한-사항) 참고).
- **각자 하나씩, 다른 사람은 볼 수 없습니다.** 각 프로필마다 4~6자리 PIN을 설정할 수 있습니다. 관리자는 프로필을 생성, 삭제하고 PIN을 재설정할 수 있지만, 모든 콘텐츠 엔드포인트는 관리자 키에 대해 403을 반환하므로 북마크를 볼 수 있는 **경로 자체가 없습니다**. 이는 관리자나 LAN에 대한 암호학적 방어(LAN 내에서 쿠키를 변조하면 누구로든 위장 가능)가 아니라, 서버가 각 프로필을 완전히 분리하여 관리하기 위함입니다.
- **실수로 변경해도 되돌릴 수 있습니다.** 일괄 변경 전에는 항상 스냅샷을 먼저 생성합니다. '되돌리기'에서는 각 이전 버전에 몇 개의 북마크와 그룹이 있었는지 확인할 수 있으며, 복원 전 현재 버전도 자동 저장되므로 잘못 되돌린 작업도 다시 되돌릴 수 있습니다. 기록은 추가만 되고 삭제되지 않습니다: 누가, 언제, 어떤 경로(웹페이지, AI, 확장 프로그램, CLI)로 어떤 항목을 수정했는지만 기록하며, 수정된 내용 자체는 기록하지 않습니다.

## 지원 범위

| 항목 | 지원 여부 |
|---|---|
| 실행 방식 | `docker compose up -d`, 또는 정적 바이너리 (amd64 / arm64) |
| 실행 환경 | 홈 NAS, 라즈베리 파이, 소프트 라우터, 또는 사내 인트라넷 머신 |
| 사용자 | 1인, 가족, 또는 소규모 팀 — 각자 1개 프로필; 관리자는 계정만 관리하고 콘텐츠는 다루지 않음 |
| 브라우저 | 모든 최신 브라우저; JavaScript를 꺼도 모든 북마크가 표시되고 클릭 가능함 |
| 설치 요구사항 | Docker만 필요: 서드파티 라이브러리 없음, 데이터베이스 없음, 빌드 시 Node 불필요 |
| 데이터 저장 위치 | 일반 디렉터리인 `data/`; 통째로 복사하면 백업 완료 |
| 인터페이스 언어 | 4개 인터페이스 언어 (간체 중국어, 번체 중국어, 영어, 아랍어 RTL). 설정 시 머신 기본값을 선택하고, 이후 각 프로필별로 개별 변경 가능 |

## 주요 기능

**저장과 정리**

- **드롭하면 바로 저장**: 북마크 바, 주소창, 또는 다른 탭에서 링크를 원하는 그룹으로 드래그 앤 드롭하세요. 팝업 대화상자 없이 드롭한 위치에 바로 저장됩니다.
- **드래그하여 순서 변경**: 그룹 내 위치 변경, 다른 그룹으로 이동, 그룹 제목에 드롭하여 맨 뒤에 추가할 수 있습니다. 길게 누르거나 단축키를 눌러 다중 선택 모드로 진입하면 한 번에 태그 지정, 이동, 삭제가 가능합니다.
- **어디서든 저장**: 북마크릿을 북마크 바에 드래그해 두면, 어떤 웹페이지에서든 클릭 한 번으로 주소를 가져오고 한 번 더 눌러 저장합니다.
- **브라우저에서 가져오기**: Chrome / Edge / Firefox에서 내보낸 HTML 파일을 업로드하면 항목별 대조 리포트(추가된 항목, 제외된 항목 및 이유)를 제공합니다. 웹페이지에서 즉시 가져올 수도 있고 리포트를 먼저 확인할 수도 있습니다. CLI는 `--dry-run`을 주지 않는 한 한 번에 기록합니다.
- **프로필 통째로 이동**: 북마크**뿐만 아니라** 페이지의 외형 설정(테마, 배치, 보기 방식, 보조 설명 줄, 페이지 이름, 언어, 주소 모드)까지 단일 파일에 담깁니다. PIN, 프로필 식별 정보, 배경 이미지는 의도적으로 제외됩니다.

**찾기**

- **그룹과 검색**: 상단 바에서 이름, 주소, 메모, 태그를 검색합니다. Enter를 누르면 서버에서 결과를 반환하므로 JavaScript가 필요 없습니다. 스크립트가 켜져 있으면 `/` 키 또는 `⌘/Ctrl K` 팔레트를 사용할 수 있습니다.
- **더 크게 표시된 그룹**: 자주 쓰는 그룹을 '대형 카드'로 지정하면 페이지 상단에 큼직한 카드로 모아서 보여줍니다.
- **10,000개 이상의 아이콘, 오프라인 지원**: Tabler와 Simple Icons를 바이너리에 gzip 압축하여 내장했습니다. 사이트 favicon은 한 번 가져오면 로컬 캐시에서 제공됩니다.

**집에서나 밖에서나**

- **북마크 하나에 주소 두 개**: 기본 주소와 선택적 외부망(WAN) 주소를 설정할 수 있습니다. '자동'은 launchbay에 접속한 주소를 따르고, '설정 → 북마크 주소'에서 브라우저별로 수동 변경할 수 있습니다. 검색과 복사는 현재 활성화된 주소를 사용하며, 외부망 주소가 없는 북마크는 기본 주소를 계속 유지합니다. 역방향 프록시 뒤에서는 원래의 `Host` 헤더를 유지해야 합니다.

**페이지 자체의 기능**

- **통합 설정 패널**: 상단 바 → 설정. 페이지 외형과 언어, 그룹 목록, 백업 및 기록, 그리고 관리자를 거치지 않고 직접 프로필을 잠그거나 풀 수 있는 **내 PIN** 설정이 한곳에 있습니다.
- **오프라인에서도 동작**: 최근 페이지가 브라우저에 캐시되며, 오프라인 상태이거나 머신이 꺼져 있을 때 추가한 북마크는 큐에 대기했다가 다시 연결되면 자동 재전송됩니다. 서버 자체가 내려가 있었다면 **지금 보내기**를 누르면 됩니다.
- **스크립트와 AI를 위한 독립 키**: 확장 프로그램, CLI, 자동화를 위한 REST API와 프로필 전용 토큰을 제공합니다. 본인 프로필 범위를 벗어나는 토큰은 403으로 거부됩니다.

## 빠른 시작

```bash
git clone https://github.com/rockbenben/launchbay
cd launchbay
docker compose up -d
```

`.env` 파일이나 Go 환경 구축이 필요 없습니다. 이미지가 직접 다운로드됩니다.

LAN 내의 **모든 기기**에서 **http://<이 머신의 내부 IP 주소>:7600**에 접속하세요. **`localhost`를 사용하지 마세요.** 이는 '현재 기기'를 의미하므로, 스마트폰 브라우저에 입력하면 스마트폰 자체를 열려고 시도하게 됩니다. 머신 자체에서 직접 접속할 때는 `http://localhost:7600`을 사용할 수 있습니다.

이미지 태그는 `:latest`입니다. 최초 `up` 시 최신 릴리스를 다운로드합니다. 이미 구동 중인 머신에는 로컬 이미지가 남아 있으므로 업데이트 시 먼저 `docker compose pull`을 실행하세요.

> **먼저 기본 관리자 키를 변경하세요.** compose 파일에는 공개 기본값인 `launchbay123`이 설정되어 있습니다. 같은 LAN 내에서 이를 아는 사람은 누구나 프로필을 생성, 삭제하고 PIN을 변경할 수 있습니다(북마크 열람은 여전히 불가능). 본인만의 키를 `LAUNCHBAY_ADMIN_TOKEN`에 설정하고 다시 `docker compose up -d`를 실행하세요:
>
> ```yaml
> LAUNCHBAY_ADMIN_TOKEN: "나만의-관리자-키"
> ```

접속하면 1회성 초기 설정 페이지가 열립니다: 첫 프로필의 이름을 정하고 4~6자리 PIN을 설정합니다. 기본 계정이나 암호는 없으며, 디스크에 프로필이 하나라도 생성되면 이 설정 페이지는 영구적으로 닫힙니다.

**'PIN 없음'은 별도의 체크 항목이며, 빈칸으로 두는 것이 아닙니다.** PIN을 빈칸으로 두면 생성이 거부됩니다. **PIN 없음**에 체크해야만 LAN 내 누구나 접근할 수 있는 열린 프로필이 생성됩니다. 이는 의도된 설계입니다. 번호를 덜 누르고 실수로 Enter를 쳐서 개인 북마크가 온 가족에게 조용히 공개되는 치명적인 실수를 방지하기 위함입니다. PIN이 없는 프로필은 선택 화면에 PIN 입력란 자체가 나타나지 않습니다. 나중에 **내 PIN**에서 추가하거나 해제할 수 있으며, 해제할 때는 기존에 PIN이 설정되어 있던 경우에만 이전 PIN을 요구합니다.

첫 번째 프로필은 **관리자가 아닙니다**. 머신 관리는 `LAUNCHBAY_ADMIN_TOKEN`으로 수행합니다: `/admin`을 열고 키를 한 번 입력하면 관리자 권한 전용 쿠키(유효기간 30일)가 발급됩니다.

**나중에 합류하는 가족은 관리자를 기다릴 필요가 없습니다.** 선택 화면에 접혀 있는 **"자신을 위한 새로운 것"** 메뉴가 있습니다. 펼쳐서 이름과 PIN을 입력하면 즉시 새 프로필이 생성됩니다(`POST /new`; 머신용 경로는 `POST /api/v1/profiles/new`). 별도의 인증이 필요 없으므로 LAN 내 어떤 기기에서든 생성할 수 있습니다. 생성 즉시 선택 화면에 카드가 추가되며, 관리자는 언제든 이를 삭제할 수 있습니다. 생성되는 프로필은 **빈** 상태이며 본인의 PIN에만 귀속되고 다른 사람의 북마크에 대한 열람 권한은 전혀 부여하지 않습니다. 이름은 최대 60자까지 입력 가능하며, 다른 사람과 같은 이름을 쓰면 두 카드를 구분하기 어려워집니다.

**프로필 삭제는 유일하게 되돌릴 수 없는 작업입니다.** 따라서 확인 화면에서 다시 확인합니다: 삭제될 북마크 수와 스냅샷 수가 명시되며, `LAUNCHBAY_ADMIN_TOKEN`을 한 번 더 입력해야 실제로 삭제됩니다. 머신용 경로(`DELETE /api/v1/profiles`)는 오직 이 키만 허용하며 관리자 쿠키만으로는 403이 반환됩니다. 스냅샷과 개인 배경 이미지도 프로필과 함께 완전히 삭제되므로 '되돌리기'로 복구할 수 없습니다.

동일 페이지에 **인터페이스 언어** 드롭다운이 있어 설정 시 함께 선택할 수 있습니다. 이는 **머신 전체의 기본값**을 지정하며, 이후 각 사용자는 자신의 패널에서 원하는 언어로 바꿀 수 있습니다. 관리자가 변경한 기본값은 아직 언어를 직접 선택하지 않은 사용자에게만 적용됩니다.

### 관리자 키와 토큰

| 환경 변수 | 필수 여부 | 관리 범위 |
|---|---|---|
| `LAUNCHBAY_ADMIN_TOKEN` | **필수**, 단일 키 | 계정 관리 전용: 프로필 생성/삭제, 임의의 PIN 설정, 비활성화/활성화, 프로필 간 종합 상태 및 기록 확인. 모든 콘텐츠 엔드포인트(`/api/v1/data`, `/batch`, `/export` 등)는 403을 반환하며 북마크를 읽을 수 없음 |
| `LAUNCHBAY_WRITE_TOKENS` | 선택, 기본값 비어 있음 | 프로필 범위 쓰기 토큰 (`name:secret:profile`, 즉 이름:시크릿:프로필). 브라우저 확장 프로그램, CLI(`revert` / `import-bookmarks` / `backup` / `restore` / `profile fix-names`), AI 및 스크립트에서만 필요함 |

> **왜 기본값이 비어 있나요?** 북마크 페이지, 관리자 페이지, 되돌리기, 가져오기 등은 모두 세션 쿠키로 동작하므로 토큰이 전혀 필요하지 않습니다. 토큰이 필요한 도구들은 사용자가 의도적으로 설치하는 것들입니다. 기본값을 제공하면 모든 머신에서 가장 흔한 프로필 ID인 `dad`를 수정할 수 있는 키를 무료로 배포하는 셈이 됩니다.

프로필 자체에는 '관리자 여부' 속성이 없습니다. 관리자 페이지에는 계정 수준의 작업과 함께 각 프로필의 항목 수, 버전, 최근 변경 일시, PIN 미설정 여부가 표시됩니다.

> **프로필 ID는 이름에서 파생되며 반드시 `dad`가 되는 것은 아닙니다.** ASCII 영문과 숫자는 슬러그로 변환됩니다(`Dad` → `dad`, `nas box` → `nas-box`). 한국어나 중국어 등 비 ASCII 이름은 슬러그를 만들 수 없으므로 `home`, `home-2` 순번으로 자동 배정됩니다. 이때 `…:dad`로 지정된 토큰은 어떤 프로필과도 일치하지 않아 403 오류가 발생합니다. 토큰 범위를 실제 ID로 수정하거나(권장), 첫 프로필 이름을 ASCII 영문으로 지으세요.

호스트 포트 기본값은 7600입니다. 일부 Windows 머신에서는 Hyper-V가 특정 포트 대역(테스트 환경에서는 7532–7631)을 점유하고 있을 수 있습니다. `up` 실행 시 포트 충돌이 발생하면 충돌하지 않는 다른 포트를 지정하세요: `LAUNCHBAY_HOST_PORT=8901 docker compose up -d` (컨테이너 내부 포트는 변경되지 않습니다). 프로젝트명과 컨테이너명은 `launchbay`로 고정되어 있으므로 어떤 디렉터리에 clone하든 `docker logs launchbay`, `docker exec launchbay …` 명령이 정상 작동합니다.

### 브라우저 확장 프로그램 (선택 사항)

`extension/`은 Chrome / Edge용 확장 프로그램(Manifest V3)입니다: 현재 웹페이지를 우클릭하여 지정된 프로필에 저장하거나, 현재 창의 모든 탭을 한 번에 저장할 수 있습니다. Docker 이미지에는 포함되어 있지 않으므로 수동으로 설치해야 합니다.

확장 프로그램은 세션 쿠키를 읽을 수 없으므로 프로필 범위의 토큰이 필요합니다. `LAUNCHBAY_WRITE_TOKENS`를 입력하고 서비스를 재시작한 후 다음 단계를 진행하세요:

1. `chrome://extensions`를 열고 우측 상단 **개발자 모드**를 켭니다.
2. **압축해제된 확장 프로그램을 로드합니다**를 클릭하고 `extension/` 폴더를 선택합니다.
3. 확장 프로그램의 옵션 페이지를 열고 머신 주소(끝의 슬래시 제외), 기본 프로필 ID, 토큰의 시크릿 값을 입력합니다.
4. **이 머신 테스트**를 클릭합니다.

테스트 시 403이 반환되는 것은 네트워크 오류가 아니라 토큰과 프로필 ID가 일치하지 않기 때문입니다. `LAUNCHBAY_WRITE_TOKENS`의 범위를 수정한 후 재시작하고 다시 테스트하세요.

설치 완료 후: 임의의 웹페이지에서 우클릭하여 바로 저장할 수 있습니다. 옵션 페이지에서는 브라우저 북마크 트리 전체를 가져올 수도 있으며, 북마크 권한은 최초 사용 시에만 요청합니다. 3가지 가져오기 경로(웹, 확장 프로그램, CLI)는 모두 **빈 프로필에만 가져오기 가능**합니다(기존 데이터에 덧붙이지 않고 프로필 전체를 교체함). Chrome에서 "모든 웹사이트에 있는 데이터 읽기 및 변경" 경고가 뜨는 것은 우클릭 이벤트 처리에 `http://*/*` 및 `https://*/*` 권한이 필요하기 때문입니다. 토큰은 `chrome.storage.local`에만 로컬 보관되며 동기화되지 않습니다. Firefox는 아직 검증되지 않았습니다.

### 데이터 디렉터리 권한

데이터는 `docker-compose.yml`과 같은 위치의 `./data`에 기본 저장되며, 컨테이너 내부에서는 항상 `/data`입니다. 다른 위치로 변경하려면 `volumes` 설정을 수정하세요:

```yaml
    volumes:
      - /volume1/docker/launchbay:/data
```

Windows 환경에서 `D:`와 같은 절대 경로를 사용할 때는 콜론이 구분자와 충돌하므로 긴 형식의 문법을 사용하세요:

```yaml
    volumes:
      - type: bind
        source: D:/launchbay-data
        target: /data
```

컨테이너는 **uid 65534**로 실행되지만 호스트 디렉터리는 보통 root 소유이므로, 프로필 생성, 가져오기, 북마크 쓰기가 실패하게 됩니다. 호스트에서 해당 사용자에게 소유권을 부여하세요:

```bash
sudo chown -R 65534:65534 ./data
```

`--user root`로 우회하지 마세요. 서비스가 root 권한으로 호스트의 모든 파일을 수정할 수 있게 되어 보안상 위험합니다. 헬스체크는 검사 시마다 데이터 디렉터리 내에 프로브 파일을 생성 및 삭제하므로, 권한이 잘못되면 `docker ps`에서 **unhealthy**로 표시되며 로그에도 동일한 chown 명령어가 출력됩니다. 초기 설정 페이지에서도 동일한 안내가 제공됩니다(컨테이너 내에서는 `uid 65534`, 바이너리 직접 실행 시에는 실행 계정).

## 사용 방법

| 하고 싶은 작업 | 위치 |
|---|---|
| 페이지 외형, 보기 방식, 그룹, 배경, 주소 모드 및 열기 방식 변경 | 상단 바의 '설정', 또는 `POST /prefs`, `/prefs/background`, `/prefs/group`, `/prefs/tabs` |
| 내 PIN 변경 | 내 패널의 '내 PIN', 또는 `POST /prefs/pin` / `POST /api/v1/profiles/self/pin` |
| 프로필 생성/삭제, 타인의 PIN 설정, 비활성화 | `/admin` (또는 선택 화면 하단의 관리 링크). 삭제 시 키 재입력 필요. 계정 관리 CLI는 `profile create`와 `profile rebuild`만 지원 |
| 나를 위한 프로필 하나 더 만들기 | 선택 화면의 접혀 있는 '자신을 위한 새로운 것', 또는 `POST /api/v1/profiles/new` (인증 불필요) |
| '이름이 주소 그대로인' 항목 정리 | `launchbay profile fix-names --profile <id>` (먼저 `--dry-run` 추가) |
| AI나 스크립트로 북마크 수정 | `POST /api/v1/batch` (`expectedRev` 포함) |
| 손상된 프로필 복구 | `POST /api/v1/profiles/rebuild`, 또는 `launchbay profile rebuild` |
| 모든 변경 내역 확인 | `GET /api/v1/history` (작업 및 경로만 기록, 내용 자체는 미기록) |
| 프로필 전체 백업 또는 이동 | `GET /api/v1/backup` / `POST /api/v1/restore`, `launchbay backup` / `restore`, 또는 설정 내 '백업 및 기록' |

기타 머신용 엔드포인트: `POST /api/v1/usage` (클릭 수 기록), `POST /api/v1/resolve` (URL에서 제목과 아이콘 추출), `GET /api/v1/status` (관리자 전용 전체 프로필 요약).

백업 파일에는 PIN, 프로필 식별 정보, 배경 이미지가 포함되지 않습니다. 북마크가 포함된 백업은 빈 프로필에만 적용할 수 있으며, 설정만 담긴 백업은 언제든 적용 가능합니다. 가져오기는 프로필 잠금 하에서 리비전을 확인하며, 동시 충돌 시 409 `[rev-conflict]`와 `currentRev`를 반환합니다. 이렇게 적용된 설정은 리비전을 증가시키지 않으며 '되돌리기'에도 나타나지 않습니다.

**전체 엔드포인트 목록, 요청 본문 및 오류 코드는 [AGENTS.md](../../AGENTS.md)를 참조하세요.** 이는 AI를 위해 라우팅 테이블과 테스트로 엄격히 검증된 공식 계약 문서입니다. 여기서는 중복 설명하지 않습니다.

**CLI 사용 관례**: 작업 결과는 stdout, 실패 메시지는 stderr로 출력되며, 모든 실패 메시지에는 서버의 오류 코드(`[rev-conflict]`, `[ops-invalid]`)가 인용됩니다. `import-bookmarks`는 파일 경로를 위치 인수로 받아 검토 보고서 출력과 쓰기 작업을 동일 실행 내에서 수행합니다(`--dry-run` 지정 시 쓰기 직전에 중단). 백업 및 내보내기는 전체 응답을 스트리밍하므로 4 MiB를 초과하는 대용량 파일도 안전하게 처리합니다. `--help` 및 `-h`는 종료 코드 0, 사용법 오류는 2, 기타 실패는 1을 반환합니다. `revert --to 0`은 사용법 오류로 거부되며 실제 수행 가능한 `curl` 명령어를 안내합니다.

**자바스크립트 0개는 최소 기준이지 상한선이 아닙니다.** 검색은 기본 폼이며, 프로필 생성과 PIN 설정도 브라우저 기본 폼 전송으로 이루어져 스크립트를 꺼도 모든 북마크를 확인하고 클릭할 수 있습니다. 본문으로 바로 이동하는 건너뛰기 링크도 내장되어 있습니다. 그 위에 추가 시트, 즉석 편집, 드래그 정렬, ⌘K 팔레트, 오프라인 지원을 제공하는 점진적 향상 레이어가 올라가 있습니다. 향상 레이어가 작동하지 않더라도 기본 무스크립트 환경은 언제나 완벽히 동작합니다.

## 제한 사항

- **LAN 환경 전용, HTTPS 미지원.** 북마크 데이터는 디스크에 일반 JSON으로 저장됩니다. 외부 인터넷에 공개하기 전에 전면에 TLS 역방향 프록시를 구성하세요.
- **`profile.json`이 손상되면 해당 프로필이 잠깁니다.** `revert`로 복구할 수 없습니다. `POST /api/v1/profiles/rebuild`(또는 `launchbay profile rebuild`)는 해당 파일만 다시 생성하며 북마크, 스냅샷, 변경 기록 데이터는 전혀 건드리지 않습니다.
- **아이콘 가져오기 쿨다운**: 가져오기에 실패한 동일 출처(origin)는 24시간 동안 재시도하지 않습니다. 24시간 쿨다운을 통해 실패한 사이트에 불필요한 반복 요청이 발생하는 것을 방지합니다.
- **공유 목록 기능 없음**: 하나의 북마크를 가족과 공유하거나 특정 페이지를 외부에 공개할 수 없습니다. 각자 독립된 공간을 유지하는 것이 본 제품의 핵심 목적입니다.
- **실제 NAS 기기에서의 검증 미완료.** 모든 인수 테스트는 Windows + Docker Desktop 환경에서 수행되었습니다. LAN 환경에서의 LCP 목표치, 콜드 스타트 시 LCP, 1,000개 북마크 스크롤 프레임레이트, 오프라인 캐시 적중 지연 시간 등은 아직 측정되지 않았습니다.
- **날씨나 시계 같은 위젯 미지원.** 이는 본 대시보드가 추구하는 목적 밖의 영역입니다. 하단 텍스트와 북마크 내용은 `POST /api/v1/batch`를 통해 관리되며, 파일 관리는 서버가 담당합니다.
- **인터페이스 언어는 인터페이스에 한정되며, 스크립트용 텍스트는 제외됩니다.** API 오류 `detail`, 필드 유효성 검사 사유, 스크립트용 가져오기 보고서는 중국어로 유지됩니다(웹페이지 보고서는 페이지 언어 설정을 따름). 호출 클라이언트는 안정적이고 비교 가능한 텍스트가 필요하기 때문입니다. 또한 사용자의 북마크 제목, 그룹 이름, URL 등은 사용자의 콘텐츠이므로 번역되지 않습니다.
- **토큰은 기본적으로 비어 있으므로**, 토큰을 추가하기 전까지는 확장 프로그램과 CLI를 사용할 수 없습니다. 반대로 관리자 키는 시작 시 필수 항목입니다.

## 이미지 출처

compose는 공개된 빌드 이미지 다운로드만 담당하며 빌드는 CI가 수행합니다. `v*` 태그를 푸시하거나 워크플로를 수동 실행하면 `.github/workflows/docker.yml`이 amd64 및 arm64용 이미지를 빌드하여 Docker Hub와 GHCR로 푸시합니다. 릴리스 태그는 `<version>`, `<major>.<minor>`, `<major>`(현재 `0.4.0` / `0.4` / `0`)와 `latest`, 커밋 단축 sha가 사용되며, 이미지 버전은 오직 git 태그로부터 부여됩니다.

저장소 clone 없이 이미지를 바로 실행하려면 다음과 같이 입력하세요:

```bash
docker run -d --name launchbay -p 7600:7600 \
  -v launchbay-data:/data -e LAUNCHBAY_DATA_DIR=/data \
  -e LAUNCHBAY_ADMIN_TOKEN="나만의-관리자-키" \
  -e LAUNCHBAY_WRITE_TOKENS="ai-dad:나만의-시크릿:dad" -e TZ=Asia/Shanghai \
  --health-cmd "/launchbay healthcheck" --health-interval 30s \
  ghcr.io/rockbenben/launchbay:latest
```
