覚えきれないアドレスを 1 ページに集約：NAS の管理画面、ルーター、社内 OA、監視ダッシュボード。ブラウザのホームページに設定すれば、**ワンクリックで即座に開き、読み込み待ちはありません。**

自宅の NAS、Raspberry Pi、ソフトルーター、または社内 LAN のサーバーなど、自分自身のマシンで稼働するため、ブックマークが他人のサーバーを経由することはありません。

## なぜ launchbay なのか

この種のツールにおける主な違いは 4 点です：データが誰のサーバーにあるか、家族でどう分けるか、オフラインでも使えるか、ドラッグで整理できるか。

| 比較項目 | ブラウザ標準のブックマーク | クラウドブックマークサービス | launchbay |
|---|---|---|---|
| データの保存先 | ブラウザのプロファイルフォルダ（アカウントに連動） | ベンダーのサーバー | **自分のマシン** |
| 家族での個別利用 | ブラウザの複数プロファイルで切り替え | アカウント単位 | **各自に 1 つ、サーバー上で完全分離** |
| オフライン対応 | ローカルのみ動作 | 利用不可 | **キャッシュ + オフラインキュー** |
| ドラッグによる整理 | フォルダツリー（レイアウトされた 1 ページではない） | ほとんど非対応 | **ドロップで保存、ドラッグで並べ替え** |
| 閲覧可能な第三者 | ブラウザアカウント | ベンダー | **アプリ経由でのアクセス経路なし** |

アカウント不要、サードパーティ製スクリプトなし、テレメトリなし。外部へのリクエストは、ブックマーク追加時に対象ページ（タイトル取得）と favicon を取得する一度きりです。取得に失敗したアイコンは 24 時間クールダウンされます。

**1 人だけで使うなら、ブラウザ標準のブックマーク機能で十分かもしれません。** launchbay がもたらす価値は、次の 3 点です：

- **開くときに待たせない。** ページはサーバーサイドでレンダリングされ、スクリプトが実行される前に HTML 内にブックマークとアイコンが含まれています。LAN 内のファーストペイント LCP < 300ms を目標としています（実機 NAS でのコールドスタートは未計測。詳細は[制限事項](#制限事項)を参照）。
- **1 人に 1 つ、他人は見られない。** 各プロフィールには 4〜6 桁の暗証番号（PIN）を設定できます。管理者はプロフィールの作成、削除、PIN のリセットを行えますが、すべてのコンテンツエンドポイントは管理者キーに対して 403 を返し、ブックマークを閲覧する**経路は存在しません**。これは管理者や LAN に対する暗号学的な防御（LAN 内で cookie を偽造すれば誰にでもなりすませる）ではなく、サーバーが各プロフィールを独立して管理するための仕組みです。
- **変更の失敗も元に戻せる。** 一括変更の前には必ずスナップショットが保存されます。「元に戻す」画面では、各旧バージョンに含まれるブックマーク数やグループを確認でき、復元前に現在のバージョンも自動保存されるため、復元のやり直しも可能です。履歴は追記のみで削除されません：誰が、いつ、どの経路（Web ページ、AI、拡張機能、CLI）でどの項目を変更したかを記録し、変更後のコンテンツ自体は記録しません。

## 対応範囲

| 項目 | 対応状況 |
|---|---|
| 実行方法 | `docker compose up -d`、または静的バイナリ（amd64 / arm64） |
| 稼働環境 | 自宅の NAS、Raspberry Pi、ソフトルーター、または社内 LAN のマシン |
| 対象ユーザー | 個人、家族、または少人数のチーム — 各自に 1 プロフィール。管理者はアカウントのみを管理し、コンテンツには関与しません |
| ブラウザ | 最新の各種ブラウザ。JavaScript を無効にしてもすべてのブックマークが表示され、クリック可能です |
| 必要な環境 | Docker のみ：サードパーティ製ライブラリ不要、データベース不要、ビルド時の Node 不要 |
| データの保存場所 | 通常のディレクトリ `data/`。丸ごとコピーするだけでバックアップ完了 |
| インターフェース言語 | 4 言語のインターフェース（簡体字中国語、繁体字中国語、英語、アラビア語 RTL）。セットアップ時にマシン全体のデフォルトを選択し、その後各プロフィールで個別に設定可能 |

## 主な機能

**保存と整理**

- **ドロップして即保存**：ブックマークバー、アドレスバー、他のタブからリンクをグループへドラッグ＆ドロップ。ダイアログは表示されず、ドロップした位置にそのまま保存されます。
- **ドラッグで並べ替え**：グループ内での位置変更、グループ間の移動、グループタイトルへのドロップによる末尾追加に対応。長押しまたはショートカットで複数選択モードに入り、一括でタグ付け、移動、削除が可能です。
- **どこからでも保存**：ブックマークレットをブックマークバーに登録しておけば、任意の Web ページでクリックするだけでアドレスを取得し、もう一度押すだけで保存できます。
- **ブラウザからインポート**：Chrome / Edge / Firefox からエクスポートした HTML ファイルをアップロードすると、項目ごとの突合レポート（追加されたもの、されなかったもの、その理由）が表示されます。Web 画面から即座にインポートすることも、先にレポートを確認することも可能。CLI は `--dry-run` を指定しない限りその場で書き込みます。
- **プロフィール丸ごと移行**：1 つのファイルにブックマーク**および**ページの外観設定（テーマ、配置、レイアウト、2行目の表示、ページ名、言語、アドレスモード）が保存されます。PIN、プロフィールの識別情報、背景画像は意図的に除外されています。

**見つける**

- **グループと検索**：上部バーで名前、アドレス、メモ、タグを検索。Enter キーを押せばサーバーが結果を返し、JavaScript は不要です。スクリプトが有効な場合は `/` または `⌘/Ctrl K` パレットが使えます。
- **よく使うグループを大きく表示**：頻繁に使うグループを「大カード」に指定すると、ページ上部に大きなカードとして強調表示されます。
- **10,000 以上のアイコンをオフラインで利用可能**：Tabler と Simple Icons をバイナリ内に gzip 圧縮して内蔵。サイトの favicon は一度取得したあとローカルキャッシュから配信されます。

**自宅でも外出先でも**

- **1 つのブックマークに 2 つのアドレス**：プライマリアドレスとオプションの WAN アドレスを設定可能。「自動」を選ぶと launchbay を開いた際のアドレスに追従し、「設定 → ブックマークアドレス」でブラウザごとに手動上書きもできます。検索やコピーには現在有効なアドレスが使われ、WAN アドレスが未設定のブックマークはプライマリアドレスを引き続き使用します。リバースプロキシの背後では元の `Host` ヘッダーを保持してください。

**ページ自体の機能**

- **統合設定パネル**：上部バーの「設定」に、ページの外観や言語、グループ一覧、バックアップと履歴、そして「私の暗証番号」（管理者を通さずに自分自身のプロフィールをロック・アンロック可能）が集約されています。
- **オフラインでも動作**：直近のページがブラウザにキャッシュされ、オフライン時やサーバー停止時に追加されたブックマークはキューに蓄積され、再接続時に自動送信されます。サーバー自体が落ちていた場合は「今すぐ送信」をクリックします。
- **スクリプトや AI 専用のキー**：拡張機能、CLI、自動化スクリプト向けに REST API とプロフィールスコープのトークンを用意。自身のプロフィール外を操作しようとすると 403 で拒絶されます。

## クイックスタート

```bash
git clone https://github.com/rockbenben/launchbay
cd launchbay
docker compose up -d
```

`.env` は不要、Go の環境構築も不要です。イメージが直接プルされます。

LAN 内の**任意のデバイス**から **http://<このマシンのローカルIPアドレス>:7600** を開きます。**`localhost` は使わないでください**。「このデバイス」を指すため、スマホで入力するとそのスマホ自体を開こうとします。マシン本体の前に座って操作する場合は `http://localhost:7600` でアクセスできます。

イメージタグは `:latest` です。初回の `up` で最新リリースが取得されます。すでに稼働中のマシンにはローカルイメージが存在するため、更新時は先に `docker compose pull` を実行してください。

> **最初にデフォルトの管理者キーを変更してください。** compose ファイルには公開デフォルト値である `launchbay123` が設定されています。LAN 内でこれを知っている人なら誰でもプロフィールの作成、削除、PIN のリセットができてしまいます（ブックマークの閲覧はできません）。自身専用のキーを `LAUNCHBAY_ADMIN_TOKEN` に指定し、再度 `docker compose up -d` を実行してください：
>
> ```yaml
> LAUNCHBAY_ADMIN_TOKEN: "あなた自身の管理者キー"
> ```

アクセスすると初回セットアップ画面が開きます：最初のプロフィールに名前を付け、4〜6 桁の PIN を設定します。デフォルトのアカウント・パスワードはなく、ディスク上にプロフィールが 1 つでも作成されると、この画面は恒久的に閉じられます。

**「PIN なし」はチェックボックスであり、空欄のままにすることではありません。** PIN を空欄にしただけでは拒絶されます。「PIN なし」に明示的にチェックを入れて初めて、LAN 内の全員に公開されたプロフィールが作成されます。これは意図的な設計です。最も危険なミスは、桁数を打ち間違えてそのまま Enter を押し、意図せず個人のブックマークを家族全員に公開してしまうことです。PIN を設定していないプロフィールは、選択画面で PIN 入力欄すら表示されません。後から「私の暗証番号」で設定・解除が可能です。解除する際は、もともと PIN が設定されていた場合にのみ旧 PIN が求められます。

最初のプロフィールは**管理者ではありません**。マシンの管理には `LAUNCHBAY_ADMIN_TOKEN` を使用します：`/admin` を開いてキーを 1 回入力すると、管理者権限専用の cookie（有効期間 30 日）が発行されます。

**後から使う人も管理者を待つ必要はありません。** 選択画面には折りたたまれた「自分用に新しいものを」があります。これを展開して名前と PIN を入力するだけでプロフィールが作成されます（`POST /new`。マシン向けエンドポイントは `POST /api/v1/profiles/new`）。認証は不要で、LAN 内のどのデバイスからでも作成可能です。選択画面にカードが追加され、管理者はいつでも削除できます。作成されるのは**空の**プロフィールであり、設定した PIN のみに紐づき、他人のブックマークへのアクセス権は一切与えられません。名前は最大 60 文字まで対応しており、他の人と同じ名前にすると 2 枚のカードの見分けがつかなくなります。

**プロフィールの削除は唯一取り消せない操作です**。そのため確認画面で再度確認されます：削除されるブックマーク数とスナップショット数が明記され、`LAUNCHBAY_ADMIN_TOKEN` の再入力が求められます。マシン向けエンドポイント（`DELETE /api/v1/profiles`）はこのキーのみを受け付け、管理者 cookie だけでは 403 になります。スナップショットやプライベート背景画像もプロフィールと共に消去され、「元に戻す」で救出することはできません。

同じ画面に**インターフェース言語**のドロップダウンがあり、セットアップ時に選択できます。これは**マシン全体のデフォルト**を設定するものであり、その後各ユーザーは自身のパネルで個別に言語を選択できます。管理者が変更した設定は、まだ言語を選んでいないユーザーにのみ反映されます。

### 管理者キーとトークン

| 変数 | 必須? | 管理対象 |
|---|---|---|
| `LAUNCHBAY_ADMIN_TOKEN` | **必須**、単一のキー | アカウント管理のみ：プロフィールの作成・削除、任意の PIN 設定、無効化・有効化、複数プロフィールにまたがるステータスと履歴の確認。すべてのコンテンツエンドポイント（`/api/v1/data`、`/batch`、`/export` など）は 403 を返し、ブックマークの閲覧はできません |
| `LAUNCHBAY_WRITE_TOKENS` | 任意、デフォルトは空 | プロフィールスコープの書き込みトークン（`name:secret:profile`、つまり名前:シークレット:プロフィール）。ブラウザ拡張機能、CLI（`revert` / `import-bookmarks` / `backup` / `restore` / `profile fix-names`）、AI やスクリプトでのみ必要です |

> **なぜデフォルトで空なのか？** ブックマーク画面、管理画面、復元、インポートはすべてセッション cookie で動作するため、トークンは不要です。トークンを必要とする 3 つのツールはいずれも意図して導入されるものです。デフォルト値を提供してしまうと、すべてのマシンで最も一般的なプロフィール ID である `dad` を書き込めるキーを無償で開放することになってしまいます。

プロフィール自体に「管理者であるか否か」の属性はありません。管理画面にはアカウントレベルの操作に加え、各プロフィールの項目数、バージョン、最終変更日時、PIN が未設定かどうかが表示されます。

> **プロフィール ID は名前から生成され、必ずしも `dad` になるとは限りません。** ASCII 英数字はスラグ化されます（`Dad` → `dad`、`nas box` → `nas-box`）。日本語などの非 ASCII 名はスラグ化できないため、`home` / `home-2` のシーケンスに割り振られます。そのため `…:dad` を対象としたトークンはどのプロフィールにも一致せず 403 になります。トークンのスコープを実際の ID に修正するか（推奨）、最初のプロフィールに ASCII 名を付けてください。

ホストポートのデフォルトは 7600 です。一部の Windows マシンでは Hyper-V がポート範囲（テスト環境では 7532–7631）を占有している場合があります。`up` に失敗した場合は、競合しない空きポートを指定してください：`LAUNCHBAY_HOST_PORT=8901 docker compose up -d`（コンテナ内部のポートは変更されません）。プロジェクト名とコンテナ名は `launchbay` に固定されているため、クローン先のディレクトリに関係なく `docker logs launchbay` や `docker exec launchbay …` が動作します。

### ブラウザ拡張機能（オプション）

`extension/` は Chrome / Edge 向けの拡張機能（Manifest V3）です。開いている Web ページで右クリックして指定プロフィールに保存したり、ウィンドウ内の全タブを一括保存したりできます。イメージには含まれていないため、手動でインストールしてください。

拡張機能はセッション cookie を読み取れないため、プロフィールスコープのトークンが必要です。`LAUNCHBAY_WRITE_TOKENS` を設定して再起動した後、次の手順を行います：

1. `chrome://extensions` を開き、右上の**デベロッパー モード**を有効にします
2. **パッケージ化されていない拡張機能を読み込む** をクリックし、`extension/` ディレクトリを選択します
3. 拡張機能のオプション画面を開き、マシンのアドレス（末尾のスラッシュなし）、デフォルトのプロフィール ID、トークンのシークレットを入力します
4. **このマシンをテスト** をクリックします

テストで 403 が返ってきた場合、ネットワーク障害ではなく、トークンとプロフィール ID が一致していません。`LAUNCHBAY_WRITE_TOKENS` のスコープを修正し、再起動してから再テストしてください。

インストール後：任意のページを右クリックして保存できます。オプション画面からブラウザのブックマークツリー全体をインポートすることもでき、ブックマーク権限の要求は初回のみです。3 つのインポート経路（Web、拡張機能、CLI）はいずれも**空のプロフィールにのみインポート可能**です（追加ではなくプロフィール全体の置き換えとなります）。Chrome で「すべてのウェブサイトにあるデータの読み取りと変更」という警告が表示されるのは、右クリック対応に `http://*/*` と `https://*/*` が必要なためです。トークンは `chrome.storage.local` にのみ保存され、同期されることはありません。Firefox は未検証です。

### データディレクトリの権限

データはデフォルトで `docker-compose.yml` と同じ場所の `./data` に保存され、コンテナ内では常に `/data` です。場所を変更する場合は `volumes` 行を編集してください：

```yaml
    volumes:
      - /volume1/docker/launchbay:/data
```

Windows で `D:` などの絶対パスを指定するとコロンが区切り文字と競合するため、ロング構文を使用してください：

```yaml
    volumes:
      - type: bind
        source: D:/launchbay-data
        target: /data
```

コンテナは **uid 65534** で実行されますが、ホスト上のディレクトリは通常 root 所有となっているため、プロフィールの作成、インポート、書き込みが失敗します。ホスト側で対象ユーザーに所有権を付与してください：

```bash
sudo chown -R 65534:65534 ./data
```

`--user root` で回避しないでください。サービスが root 権限で家庭内のすべてのファイルを書き込めるようになってしまいます。ヘルスチェックは実行ごとにデータディレクトリ内にプローブファイルを作成・削除するため、権限に問題がある場合は `docker ps` で **unhealthy** と表示され、ログにも同じ chown コマンドが出力されます。セットアップ画面でも同様の案内が表示されます（コンテナ内では `uid 65534`、バイナリを直接実行する場合は実行ユーザー）。

## 使い方

| 行いたい操作 | 操作場所 |
|---|---|
| ページの外観、レイアウト、グループ、背景、アドレスモード、開き方の変更 | 上部バーの「設定」、または `POST /prefs`、`/prefs/background`、`/prefs/group`、`/prefs/tabs` |
| 自身の PIN の変更 | 自身のパネル内の「私の暗証番号」、または `POST /prefs/pin` / `POST /api/v1/profiles/self/pin` |
| プロフィールの作成・削除、他人の PIN 設定、無効化 | `/admin`（または選択画面下部の管理リンク）。削除時はキーの再入力が必要。アカウント管理用の CLI は `profile create` と `profile rebuild` のみ |
| 自分用にもう 1 つ作成 | 選択画面の折りたたまれた「自分用に新しいものを」、または `POST /api/v1/profiles/new`（認証不要） |
| 「名前がアドレスそのもの」になっている項目の整理 | `launchbay profile fix-names --profile <id>`（先に `--dry-run` を指定） |
| AI やスクリプトによるブックマークの変更 | `POST /api/v1/batch`（`expectedRev` を指定） |
| 壊れたプロフィールの修復 | `POST /api/v1/profiles/rebuild`、または `launchbay profile rebuild` |
| すべての変更履歴の確認 | `GET /api/v1/history`（操作とパスのみ記録、コンテンツ自体は非記録） |
| プロフィール全体のバックアップまたは移行 | `GET /api/v1/backup` / `POST /api/v1/restore`、`launchbay backup` / `restore`、または設定内の「バックアップと履歴」 |

その他のマシン向けエンドポイント：`POST /api/v1/usage`（クリック数のカウント）、`POST /api/v1/resolve`（URL からタイトルとアイコンを取得）、`GET /api/v1/status`（管理者用プロファイル横断サマリー）。

バックアップには PIN、プロフィールの識別情報、背景画像は含まれません。ブックマークを含むバックアップは空のプロフィールにのみ適用可能です（設定のみのバックアップはどこにでも適用可能）。インポート時はプロフィールロック下でリビジョンが照合され、競合が発生した場合は 409 `[rev-conflict]` と `currentRev` を返します。この方法で書き込まれた設定はリビジョンを進めず、「元に戻す」にも現れません。

**エンドポイントの一覧、リクエストボディ、エラーコードの完全な仕様は [AGENTS.md](../../AGENTS.md) を参照してください** — AI 向けに定義された権威ある契約であり、テストによってルーティングテーブルと厳密に突き合わされています。本ファイルでは重複して記載しません。

**CLI の仕様**：標準出力に結果、標準エラー出力に失敗を出力し、すべての失敗メッセージにサーバーのエラーコード（`[rev-conflict]`、`[ops-invalid]`）が含まれます。`import-bookmarks` はファイルを位置引数として受け取り、レポート出力と書き込みを同一実行内で行います（`--dry-run` を指定すると書き込み直前で停止）。バックアップとエクスポートはレスポンス全体をストリーミングするため、4 MiB を超えるファイルでも問題ありません。`--help` と `-h` は終了コード 0、構文エラーは 2、その他のエラーは 1 を返します。`revert --to 0` は構文エラーとして拒否され、実行可能な `curl` コマンドが出力されます。

**JavaScript ゼロは最低基準であり、上限ではありません。** 検索は通常のフォーム送信、プロフィールの作成や PIN の設定もネイティブなフォーム POST で行われ、スクリプトを無効にしてもすべてのブックマークが表示されクリックできます。組み込みのスキップリンクにより本文へ直接移動できます。その上に一層のエンハンスメント層があり、追加シート、インプレース編集、ドラッグソート、⌘K パレット、オフライン対応を提供しています。仮にこの層が機能しなくても、ゼロ JS の基本機能は常に動作します。

## 制限事項

- **LAN 内専用、HTTPS 非対応。** ブックマークの内容はディスク上にプレーンな JSON で保存されます。インターネットに公開する場合は、手前に TLS リバースプロキシを配置してください。
- **`profile.json` が破損するとそのプロフィールはロックされます。** `revert` では修復できません。`POST /api/v1/profiles/rebuild`（または `launchbay profile rebuild`）を実行すると、該当ファイルのみが再生成され、ブックマーク、スナップショット、履歴データには一切手を触れません。
- **アイコン取得のクールダウン**：取得に失敗した同一オリジンは 24 時間再試行されません。このクールダウンにより、失敗したサイトへの過剰なプローブを防ぎます。
- **共有リスト機能はありません**：1 つのブックマークを家族と共有したり、ページを公開したりすることはできません。各自が独立して保持することに特化しています。
- **実機の NAS では未検証。** これまでのすべての検証は Windows + Docker Desktop 上で行われています。LAN 内の LCP 目標値、コールドスタート時の LCP、1,000 件のブックマーク表示時のスクロールフレームレート、オフラインキャッシュヒット時のレイテンシは未計測です。
- **天気や時計のウィジェットはありません。** 本ツールの提供価値の範囲外です。フッターテキストやブックマークの編集は `POST /api/v1/batch` 経由で行われ、ファイル管理はサーバー側が担います。
- **インターフェース言語はインターフェースのみを対象とし、スクリプト向けテキストは対象外です。** API エラーの `detail`、フィールド検証エラーの理由、スクリプトが読み取るインポートレポートは中国語のままです（Web ページのレポートはページ言語に追従します）。呼び出し元には安定して比較可能なテキストが必要であるためです。また、自身のブックマークタイトル、グループ名、URL もコンテンツであるため翻訳されません。
- **トークンはデフォルトで空です**。そのためトークンを追加するまで拡張機能と CLI は使用できません。逆に管理者キーは起動に必須です。

## イメージの取得元

compose は公開されたイメージをプルするだけで、ビルドは CI が担います。`v*` タグを打つかワークフローを手動実行すると、`.github/workflows/docker.yml` が amd64 と arm64 向けにビルドし、Docker Hub と GHCR にプッシュします。リリースタグは `<version>`、`<major>.<minor>`、`<major>`（現在は `0.4.0` / `0.4` / `0`）、および `latest` とコミットの短縮 sha です。イメージのバージョンは git タグのみから決まります。

リポジトリのクローンをスキップして直接イメージを起動する場合：

```bash
docker run -d --name launchbay -p 7600:7600 \
  -v launchbay-data:/data -e LAUNCHBAY_DATA_DIR=/data \
  -e LAUNCHBAY_ADMIN_TOKEN="あなた自身の管理者キー" \
  -e LAUNCHBAY_WRITE_TOKENS="ai-dad:あなた自身のシークレット:dad" -e TZ=Asia/Shanghai \
  --health-cmd "/launchbay healthcheck" --health-interval 30s \
  ghcr.io/rockbenben/launchbay:latest
```
