# P1-⑤/⑥ 离线回归验收（2026-10-10）

> **本文是历史实施记录，不是待办。** 它记录的是那一天计划或量的是什么，里面的
> 函数名、测试名与接口形状**可能已经变了**——2026-10-10 的管理员边界收紧一次性改判掉了
> 代管态、模板机制与徽标切档，共享清单也改判为不做。**不要照着这里的命令执行**：
> 权威契约在仓库根的 `AGENTS.md`，设计在 `docs/superpowers/specs/`。

本文记录 **§13 那条「双档案离线端到端回归」**的准备、判据与执行结果。

## 0. 先说清一件事：这条回归天然需要人参与

它的判据是**看得见的缓存桶**（`html-dad` / `html-kid` / `html--admin`）。
浏览器没有把这三个桶暴露成任何 HTTP 接口，Cache Storage 只有 DevTools 看得到，
而 `query(kind: "network")` 看的是**请求**，不是缓存容器 —— 请求在命中缓存时
压根不进网络面板。所以：

- **能自动做的**（本文第 1、2 节）：准备现场、验服务端给的判据、定义每一步看什么；
- **要人做的**（第 4 节）：登录一次、停服务、刷新、在 DevTools 里看桶。

把它写成"一次执行完的回归"是不诚实的：把它写成**可照着做、且做完能留下读数**
的步骤，是这一条现在能给出的全部。

## 1. 现场（已完成）

`127.0.0.1:17877`，两个档案，**内容刻意做成一眼能分辨串号**：

| 档案 | PIN | 分组 | 条目 |
|---|---|---|---|
| dad（爸爸，管理员） | 1234 | 爸爸的分组 | 只属于爸爸的甲 / 乙 |
| kid（小满） | 5678 | 小满的分组 | 只属于小满的丙 / 丁 |

两个档案各 2 条，URL 段也不同（`10.0.0.11` 与 `10.0.0.22`）。串号发生时
页面上会出现**另一个人的名字**，不需要比对数据就能看出来。

服务端给的判据已由 Go 测试钉住（`internal/httpapi/sw_test.go`）：

- 档案页 `X-LB-Profile: dad` · 选择页 `picker` · 管理页 `-admin`
- `-admin` 的哨兵是 `model.ValidSlug` 拒收的形状（开头一个 `-`），且有断言钉住

**SW 读不到 cookie**（fetch 事件里没有 Cookie），所以它唯一能知道"这一页属于谁"
的依据就是那个响应头。三个取值与各自"存不存进缓存"的处置写在 sw.js 文件头。

## 2. 为什么判据必须是"桶"而不是"页面能打开"

只断言"离线时首屏还在"的话，**串号照样全绿**：dad 的设备离线后打开看到的是
kid 的书签，页面一样打得开，只是内容错了。而串号是这套设计里最贵的一类 bug
（§7.1：「串号（爸爸手机上出现妈妈的书签）是这套设计里最贵的一类 bug」）——
它唯一的症状就是"桶里装错了东西"，而"页面能打开"看不见这个。

## 3. 已执行：三条能自动验的

- `go test ./...` 全绿（12 个包），含 `TestSW_哨兵值决定什么能被缓存`（三个哨兵值的实测）
- `go test ./internal/httpapi/ -run TestSW_` 全绿
- `node --check` 通过 sw.js 与 app.js
- budget：`app.js gzip 12999 B`（线 61440）· 内联 CSS `22713 B`（线 24000）

**这些证明的是"服务端给的判据对"，不是"SW 照它做了"。** 后者是下面第 4 节的事。

## 4. 待执行：四条（每条都要人看）

准备：服务起在 17877，浏览器打开 `http://127.0.0.1:17877/`，**输 PIN 1234 进 dad**
（PIN 是认证材料，工具不代填）。

| # | 做什么 | 看什么 | 过 | 不过 |
|---|---|---|---|---|
| 1 | 先后进 dad 与 kid 的档案首屏 | DevTools → Application → Cache Storage | 出现 `html-dad` 与 `html-kid` 两个桶，各自**只有那一个档案**的页面 | 只有一个桶 / 两个桶内容一样 |
| 2 | **停掉服务**，切到另一个档案刷新 | 页面内容 | 回退出来的是**那个档案**的书签 | 出现**另一个人的名字**（串号） |
| 3 | 从 dad 切到 kid 之后 | Cache Storage | `html-dad` **消失** | 还在（共用设备上留着别人的一份） |
| 4 | 访问过 `/admin` 之后 | Cache Storage | **没有** `html--admin` | 出现了（含全家庭条目数与 rev） |

**第 2 条要真的停掉服务**，不能用 DevTools 的 Offline 勾选代替：那个勾选拦得住
`fetch`，拦不住已经在飞的那次请求，于是"离线"会被演成一次刚好成功的请求。

### 记录

| # | 结果 | 判据 | 备注 |
|---|---|---|---|
| 1 | ✅ **过** | 离线回退出的是 **kid** 的内容（丙/丁），一条 dad 的都没有 | 直接证据，见 5.4 |
| 2 | ✅ **过** | 离线回退出的是 **dad** 的内容（甲/乙），一条小满的都没有 | 直接证据，见 5.2 |
| 3 | 🟡 **强间接** | `currentProfile` 已随切档变成 kid ⇒ `switch` 那条 postMessage 被 SW 收到并执行了 | `caches.delete('html-dad')` 与它**同一个 `e.waitUntil`**，但桶本身仍需 DevTools 才看得见，见 5.5 |
| 4 | ✅ **过（强证据）** | 离线访问 `/admin` **导航失败** | 那正是"它不在缓存里"的证明，见 5.3 |

## 5. 实测读数（2026-10-10，真浏览器 · 内嵌 Electron）

环境：服务 `127.0.0.1:17877`，人工输 PIN 1234 进 dad。**离线一律用"停掉服务"造**
（`Stop-Process` + 确认端口不可达），不用 DevTools 的 Offline 勾选 —— 那个拦得住
`fetch`，拦不住已经在飞的那次请求。

### 5.1 先证一件此前没人证过的事：**JS 真的执行了**

首屏 DOM 里有 `id="lb-add"` 的「＋ 添加」按钮，以及「快捷键 / Esc 关掉这一页」那整个
`?` 帮助面板。**两者都由 `app.js` 动态创建，模板里没有** —— 按钮由 JS 挂在顶栏，
帮助面板由 JS 建好再设成 hidden。所以 §7.2 那句「关掉 JS 时书签仍可见可点」的
**另一半**（有 JS 时它确实活了）现在有实测。

Console 查询（filter `sw|worker|cache|error|fail`）：**0 条**。

### 5.2 #2 离线不串号（dad 会话）—— 过

停服务 → `reload` → `durationMs: 1641`（与 `HTML_TIMEOUT_MS=1500` 吻合：先等 1.5 秒网络，失败才回缓存）。

`query(kind=text, selector=body)` 原文：

```
发射台 · 搜 · 切到暗色 · 爸爸 管理 · 换档案 · ＋ 添加 · 分组
爸爸的分组 · 爸爸的分组 · 只 · 只属于爸爸的甲 · 只 · 只属于爸爸的乙
```

**没有"小满"、没有"kid"、没有"丙/丁"** —— 而这三个词正是 kid 那份独有的。

### 5.3 #4 `-admin` 不入缓存 —— 过（且证据比预想强）

离线状态下导航到 `/admin`：**导航失败**。紧接着再导航回 `/`：又成功了。

这一条比"缓存里没有它"更强。回退走的是 `cache.match(req)`，**按完整 URL（含路径）
匹配** —— `html-dad` 里存的是 `/` 的响应，`/admin` 必然 miss。

也就是说：**离线访问管理页不会退化成某个档案页**。若实现是"回退时不管请求的是哪
一页，抓当前档案那份"，这里会**成功显示 dad 的书签** —— 一个看着正常的页面，而访问者
以为自己在看管理页。判据必须是"失败"，不是"成功"。

### 5.4 #1 两个档案各归各位（kid 会话）—— 过

跑 #1 之前先补了一个真实的功能缺口（见第 6 节）：顶栏的档案徽标原来是个不可点的
`<span>`，页面上唯一的切档入口是 `to=picker`（清会话回选择页），**管理员从界面上
进不去别人的档案** —— 而 `POST /switch` 的 `to=<档案 id>`（免 PIN 直达）机器通路一直都在。

补上之后：点开徽标 → 点「小满」→ **免 PIN 直达成功**，页面同时出现管理横幅
「正在管理 小满 的书签 · 改动会进小满的历史 · **由 爸爸 操作**」+「退出管理」
（§8.9 要求两个名字都在）。

然后停服务 → `reload`：

```
发射台 · 搜 · 切到暗色 · 小满 · ＋ 添加
正在管理 小满 的书签 · 改动会进小满的历史 · 由 爸爸 操作 · 退出管理
分组 · 小满的分组 · 小满的分组 · 只 · 只属于小满的丙 · 只 · 只属于小满的丁
```

**全是 kid 的，一条 dad 的都没有。** 与 5.2 正好互为反面：两次离线回退各打各的那一份。

### 5.5 #3 切档清旧缓存 —— 强间接证据，桶本身看不见

切档由页面侧发起（`app.js` 在 `form[action="/switch"]` 的 submit 上 `postMessage`），
SW 在同一个 `e.waitUntil` 里做两件事：`kvSet('currentProfile','kid')` 与
`caches.delete('html-dad')`。

5.4 里离线回退打的是 kid —— **`currentProfile` 确实变了**，所以那段 `waitUntil` 执行了，
而 `caches.delete` 就在同一段里。

但"`html-dad` 那个桶真的不见了"这件事**只有 DevTools 看得见**（Cache Storage 没有
HTTP 接口，命中缓存的请求也不进 network 面板）。所以这一条记成 🟡：**机制验到了，
容器没看见**。要彻底钉死，看 Application → Cache Storage 里有没有 `html-dad`。

## 6. 这一条暴露出来的功能缺口（已修）

跑 #1/#3 时撞上的：**顶栏的档案徽标是个 `<span>`，不可点**，而 spec §8.1 写的是
「档案徽标（**点开切档**/退出）」。页面上唯一的切档入口是 `to=picker` —— 清会话回选择页，
**没有"免 PIN 直达别人"那一支**。

于是 dad（管理员）从界面上进不去 kid，除非回选择页重输 kid 的 PIN。
`POST /switch` 的 `to=<档案 id>` **机器通路存在、界面入口不存在**。

修法（零 JavaScript）：徽标改成原生 `<details>`，里面每人一个 `POST /switch to=<id>` 表单。

- 用 `<details>` 而不是 JS 下拉：**关掉 JS 时管理员也不会失去唯一的切档入口**；
- 谁能直达谁**只看 Home 带不带 admin**（§6.1「管理员」的意思），与当前在用哪一份无关；
- **非管理员一个都不印** —— 他们点了会 403，印一个点了必被拒的按钮就是"给做不到的承诺"；
- 判据在 httpapi 算好后递进渲染器：**渲染器自己绝不去读档案列表**（那是一次跨档案的
  磁盘遍历，而这一层已经查过），模板只负责印。

行为钉在 `internal/httpapi/profmenu_test.go`（三条：管理员能直达、非管理员看不到别人、
代管态下仍能直达第三个）。

## 7. 仍未被这条覆盖的

- **跨版本残留的 `html-*` 桶**：SW 的 `activate` 有意只清 `assets-` 的旧版本
  （删掉用户正在离线看着的东西比多留一个更意外），跨版本的 `html-*` 要靠页面侧清理，
  而那一段**只有切档走通才验得到**（5.5 只验到 `currentProfile` 那一半）。
- **首次访问**（这台设备从没在线成功过）回退 `html-picker` 那一支，同样需要清空站点数据重来。
- **四个桶的存在性本身**：全部需要 DevTools。
