## 0. 为什么切在这里

P1-③ 的交接清单（`docs/superpowers/plans/…plan3…md` 附录 B）列了八件事，核对仓库后发现它们不是
一件，是三件互不共享流程的子系统：

| 切片 | 内容 | 判据 |
|---|---|---|
| **④ 外壳**（本文件） | 顶栏、侧栏与档案级 layout、管理横幅、`/switch`、`/admin` 读侧、主题写通路、坏档页文案、§7.3 预算闸 | 纯服务端渲染 + 表单，**零 JavaScript**，不碰书签写通路 |
| ⑤ 交互写通路 | 添加浮层（吃已上线的 `resolve`）、就地编辑、⌘K 面板、§7.5 五条键位、`/admin` 的写动作、带指纹的静态资产通路 | 第一次"从界面写库"，需要 JS 才能发 JSON |
| ⑥ 离线 | Service Worker、`html-<profileId>` 缓存名防线、离线待办队列与 409 逐条提示、双档案离线端到端回归 | 它的正确性判据是"串号 = 最贵的一类 bug" |

顺序 ④→⑤→⑥ 不是偏好：⑤ 的浮层要往 ④ 建的顶栏里放；⑥ 的缓存名防线要有真实 HTML 可缓存才测得动。

**核对后补一句：P1 还欠两件不属于 ④⑤⑥ 中任何一件的**——§9 的 **flare 导入器与对账报告**，
与 §6.3 的 **bookmarklet**（仓库里今天都没有：`cmd/launchbay` 没有 import 子命令，路由表里没有
bookmarklet 通路）。它们才是"能替换 flare"的字面前提：没有导入器，那 42 条真实书签进不来；
没有 bookmarklet，浏览器里点一下就收藏这条路不存在。本文件不吞掉它们，只登记：
**导入器应在 ④ 之后、⑤ 之前或并行做**（它纯服务端、零 JS、不依赖外壳），bookmarklet 随 ⑤
（它要落进 ⑤ 的添加通路）。§10 的预算夹具因此按"当前真实规模"写，不拿一个还没到手的 42 当基线。

**④ 零 JS 的判据**：主题切换可以是"表单 POST + 303 回原页"（局域网里少一次无刷新，肉眼看不出来）；
侧栏抽屉可以是原生 `<details>`；搜索可以是 `GET /?q=` 服务端过滤。三条都不需要 JS——那么 ④ 就没有
任何 JS 要发，§7.1 那条 `/*.<hash>.css|js` 的带指纹通路会变成**一条没有货的管道**。管道与它的第一个
包裹同批验收，所以资产通路归 ⑤。附带好处：§7.2 那句"关掉 JavaScript 时全部书签仍可见可点"在
零 JS 的 ④ 里天然成立，而 ④ 把它写成一条可测断言（§10），⑤ 落地时那条断言会红——那是它该红的时刻。

## 1. 渲染缓存键：同一份数据能长出几种页面

今天的键是 `(profileId, rev, bookmarks.mtime, iconGen)`。④ 引入三种"同一个档案、同一份
`bookmarks.json`、页面却必须不同"的情形，键必须跟着长：

1. **管理态**（§8.9 横幅）。横幅文字与「退出管理」指向都取决于 `lb_home`，而页面渲染的是
   `lb_profile` 的书签。键不带这一维 → 管理员先看一眼妈妈的台，带横幅的 HTML 就被缓存成
   "妈妈看自己"的页面（或反过来，横幅漏给管理员）。这是 §7.1 点名最贵的那类串号，且是 ④ 新引入的。
   键加 **`home`**（不是 `bool`）——两个不同管理员看到的横幅文字也不同。而横幅印的是 home 的
   **显示名**，所以这一维不能只是一个 id：home 那份 `profile.json` 的内容指纹（`homeFingerprint`）
   也要进键，否则管理员改了自家名字，代管页继续端旧名字。
2. **主题与档案级 layout**。它们在 `profile.json` 里，而现有 `mtime` 是 `bookmarks.json` 的。
   改主题不重算 = 按了没反应。键加 **`profileFingerprint`**——`profile.json` 字节的 sha256，
   由 `LoadProfileWithFingerprint` 在同一次读盘里一并给出（不额外 stat）。指纹而不是 mtime：
   tmpfs/overlayfs 与 CIFS/9p 的时间戳粒度能让「改了而页面不动」在真部署上发生（验收实测）。
   这条顺手拆掉 P1-③ 最终评审埋下的雷。
3. **搜索 `?q=`**。**不进内存缓存**——否则键空间从"每档案一份"变成"每档案每次击键一份"，
   为一个局域网页面养无界缓存不值。带 `q` 的请求直接现渲染，但**照样发 ETag**（内容哈希），
   浏览器 304 那一路不损失。

最终键：`(profileId, home, homeFingerprint, rev, bookmarksMtime, profileFingerprint, iconGen)`，`q` 走"不缓存"旁路。两处指纹都不是 mtime：横幅印的是 home 的显示名，而 tmpfs/overlayfs 与 CIFS/9p 的时间戳粒度撑不住"改了立刻看得见"。

**配对纪律**：`profFingerprint` 与 `/prefs` 端点必须同批落地。端点先落、键后改，中间那个提交里
主题按钮是死的——实施计划里排成一步或紧邻两步，不许拆成两个阶段。

## 2. 两条通路，两种"拒"

仓库里第一次同时存在 API 通路（`/api/v1/*`，吃 JSON）与浏览器通路（`/pin`、`/prefs`、`/switch`、
`/admin`，吃表单）。**表单发不出 JSON**，所以浏览器通路不能复用 API 端点，反之亦然。

- **API 通路的"拒"** = 401 / 403，逐字不变（§6.1 的"401 与 403 永远分开"）。
- **浏览器通路的权限类拒绝**（没凭证、作用域不符、非管理员撞 `/admin`）= **303 回档案选择页**，
  不报错。理由有两条：一是 §8.8 明写"非管理员访问直接回档案选择页，不报错——少一种枚举面"；
  二是给家属看 403 页面本身就是坏体验。
- **但 PIN 输错不是权限拒绝，不许一起翻译成 303。** 它今天的行为是回选择页并带 `?err=` 提示
  （`pinNotices` 那张表），家属要能看见"再试一次"。④ 不动它。这条区分进 §12 的测试。

这条映射要写进 §6.1 与 `AGENTS.md`，否则下一个人在 `/admin` 看到 303 会当 bug 修成 403。

**三处同步一处都不能少**：`routes()` 是唯一注册来源，而 `TestOpenAPICoversEveryRoute` 遍历的是
**全部**路由（不只 `/api/v1/*`）——所以 `/prefs`、`/switch`、`/admin` 三条**必须同时进
`openapi.json`**（含 `x-credential` 与 `security`，与路由表的 `Cred` 对上）、进 `AGENTS.md` 端点表
（它们不在 `/`、`/pin`、`/healthz` 那三条豁免里），并在说明列写明"仅会话、浏览器表单通路、AI 不走这条"。

## 3. `POST /prefs`：主题与档案形态

- 凭证：`credSession`。令牌一律拒——与 `POST /api/v1/profiles/self/pin` 同族同判据（"谁能改谁"）。
- 体（form）：`theme` ∈ `auto|dark|light`、`layout` ∈ `sidebar|topbar`。值集**直接复用** `model`
  已有的 `allowedTheme` / `allowedLayout`，不在 httpapi 里再抄一份枚举。
- 缺字段 = 不改那一项；**两个都缺 = 422**（"没有要改的东西"要说出来，不许静默 200）。
- 非法值 = 422 + 现成的 `fieldError` 外壳点名是哪个字段。
- 写段照 `pinapi.go` 已裁过的形状：**读→改→验→写整段进 `WithProfileLock`**；读失败分诊复用
  `writeProfileReadFailure`（404 / 坏档 503 / 其余 500），不新造第四种口径。
- 成功 303 回 `/`。不产生 `rev`、不写历史行——与"改自己 PIN"同口径，这条补进 §15 的审计例外清单。
- **管理态下改的是 `active` 档案**（家长在管理孩子时按主题，改的是孩子的偏好）。这与"管理员能替她
  设 PIN"是同一条权力线，而横幅那句话本来就在提醒这件事。
- 顶栏控件：一枚循环按钮（`auto→dark→light→auto`），`<form method=post>`，零 JS。
- **不建 JSON 版 `/api/v1/profiles/self/prefs`**。AI 替你换主题没有真实需求，而每多一条 API 面
  就要 `routes()` + openapi + AGENTS.md + 契约测试四处同步。⑤ 若要无刷新切换再加，届时两个入口
  必须共用同一个写函数——判据只留一份。

## 4. `POST /switch`：退出管理、回选择页、管理员直达

`credSession`，成功 303 回 `/`。一个端点三件事：

| 体 | 语义 | 判据 |
|---|---|---|
| `to=home` | 退出管理（`active` 设回 `home`） | 非管理态收到 = 无操作，幂等不报错；只需 `lb_home` 合法，不给任何新权限 |
| `to=picker` | 清两条会话 cookie 回选择页 | 任何有效会话都可以 |
| `to=<档案id>` | 免 PIN 直达别的档案 | **当前 `lb_profile` 指向的档案 `Admin` 为真**，服务端回查磁盘、不信 cookie 形状 |

第三条**不是新权力线**：§6.1 已经把"免 PIN 切档的许可由当前在用的那个档案的 `admin` 标记给出"写死，
并且明写它的后果——管理员进入他人档案后想再进第三个，得先退出管理。④ 做的只是**把这条已裁定的规则
落成一条路由**（今天还没有 `/switch`，`profile.tmpl` 里那条注释就是在等它）。判据取 `active` 而不是
`home` 是有意的：伪 `lb_home=dad` 换不到切档；伪 `lb_profile=dad` 能——但那条 cookie 本来就已经让他
直接是 dad 了（§6.1 原文），所以这条规则不扩大暴露面。普通成员切档仍然走 `/pin`（要 PIN）。

三条各配测试，其中"非管理员在别人的档案里伪造 `to=` 跳第三个"必须被拒——那正是 §6.1 那句话的证人。

## 5. 管理横幅（§8.9）

- 位置：`<header>` 之后、`<main>` 之前；`position: sticky; top: 0`（"不随页面滚走"）。
- 内容：`正在管理 <b>妈妈</b> 的书签 · 改动会进她的历史 · [退出管理]`（表单按钮 → `to=home`）。
  两个名字都要在 DOM 里——只有"正在管理"没有对象名，等于没提醒。
- 高对比不靠颜色：`forced-colors` 下保留边框（§7.5 既有规则，横幅要跟着满足）。
- 不加 `aria-live`：它是初始内容，播报不了，只会给屏读添噪。
- §13 收三条 DOM 断言：管理员看自己**不得**出现横幅；管理员看别人必须出现且两个名字都在；
  非管理员永远不出现（伪造 cookie 会被 `Session.Valid()` 挡在门外，那条已有测试覆盖，这里补一条）。

## 6. `GET /admin`：④ 只做读侧

- 鉴权：`require(credAdmin, "")` 判定，失败在浏览器通路翻译成 303 回选择页（§2 的映射）。
- 内容：一行一个档案 + 条目数 + `rev` + 最近改动时间，**不含条目内容**。行集与
  `handleStatus` 同一套（`ListProfiles ∪ Broken()`），复用不重写第二份聚合。
- 动作：只有「进入编辑」（§4 的 `to=<id>`）。在 `/admin` 这一页上 `active == home`，所以 §4 那条
  "看当前在用档案的 `admin` 标记"的判据在这里等价于"这个人是管理员"——不需要第二条判据。
- **设 PIN / 从模板建档 / 删档三个按钮这一版不渲染**——不是禁用、不是"敬请期待"，就是不出现。
  理由：表单发不出 JSON，硬做就要给每个动作配一条 form 端点，等于把 API 面抄一遍。它们随 ⑤
  的 JS 落地。这条与「＋添加」是同一条规则：**点了没反应的东西不进界面**。

## 7. 侧栏与档案级 layout（§8.2）

- `layout: sidebar`：桌面 190px 常驻左栏（分组锚点 + 计数 + 色点）；≤1100px 收抽屉；≤700px 变顶部
  横向标签行。`layout: topbar`：分组横向标签行常驻顶栏下方。
- 抽屉用原生 `<details>`：键盘开合与可及性免费，不值得为它写 JS 或加 checkbox 黑话。
- 锚点复用既有 `id="g-<id>"`（§8 的 section 已经带 `aria-labelledby`）。
- **带 `q` 时侧栏计数按命中数显示**——否则"5 个分组"与屏幕上实际渲染的内容对不上，又是一句谎。

## 8. 搜索 `GET /?q=`

- 服务端过滤，字段集：条目 `name` / `alias` / `url` / `tags` / `desc` + 分组 `title`。
  大小写不敏感；CJK 按子串（不分词）。
- 命中要说出来（"命中 3 条 · 共 25 条"），且**"搜索无结果"与"这个档案还没有书签"必须是两句话**——
  现在模板里只有一句 `这个档案还没有书签。`，带 `q` 时它会撒谎。
- 不进内存缓存（§1.3），照样发 ETag。
- **没有会话时 `q` 被忽略**（选择页没有书签可筛），且选择页的表单不许把 `q` 带进 PIN 环节——
  那会造出一条"带着别人的搜索词进门"的怪路径。
- `q` 是纯读侧参数，不参与任何权限判定，也不写任何东西。

## 9. 坏档页文案（部署验收 #4）

`broken.tmpl` 现在把 `err.Error()` 原样印给家属（`bookmarks.json: unexpected end of JSON input`）。
改成两层：

- 第一句是人话主句（模板里写死，不进 Go 错误链）；
- store 给的原文（含文件名与行号）收进 `<details>` 展开可见。

**文件名与行号不许丢**——§12 要求报得出位置，而修文件的人就是家长本人。`store` 的错误文本
一个字都不改：它是 API 503 的 `detail`，两处共用同一份真相，不许为了一张页面把详情拆成第二套。

## 10. 预算闸与最薄 CI

**预算进 `go test`**（`internal/render/budget_test.go`）：

- 夹具按**当前真实规模**（`dad` 25 条）+ 一份 **200 条**的余量夹具。不拿 §9 那 42 条当基线——导入器
  还没做（§0），拿一个还没到手的数当闸，红了也没人知道该找谁；
- 首屏 HTML gzip ≤ 120KB（**在测试里算 gzip 尺寸，不加 gzip 中间件**——局域网里 33KB 的传输
  时间远小于一次往返，加一层压缩换来的性能是零，换来的是"每个响应都要想 Content-Encoding
  与 ETag 怎么相处"）；
- 内联 CSS ≤ 40KB；
- `HTML 里 <script 计数 == 0`：把 §7.2 那句"关 JS 也能看能点"从修辞变成可测形状，也是 ④ 零 JS
  的守门人。⑤ 落地时它会红，那时按 ⑤ 的预算改写它，而不是现在预支。

**一条最薄 workflow**（`.github/workflows/ci.yml`）：`go vet ./...`、`gofmt -l .`、
`go test ./...`、`CGO_ENABLED=0 go build ./...`，加**泄漏守卫**（IP 字面量扫描，P1-③ 验收已跑过
同一条命令，收进 CI 零新机制，而内网拓扑进公开仓是唯一"不可撤回"的那类错误）。

**LCP / 帧率 / SW 命中不进 CI**：§7.3 那三条要真浏览器 + 真网络，而 headless 的默认值陷阱这一期
刚踩过（`prefers-reduced-motion` 默认报 `reduce`，六张主图差点全拍成动效关闭态）。假闸比没闸贵。
这三条留在人工实拍清单里，写清怎么测。

## 11. 明确不做

- 带指纹的静态资产通路（`/app.<hash>.js`、immutable 缓存）→ ⑤，与第一个真字节的 JS 同批。
- ⌘K 面板、§7.5 五条键位、就地编辑、添加浮层 → ⑤。
- Service Worker、离线待办队列 → ⑥。
- gzip 中间件、CSRF 机制、给 `/admin` 加鉴权以外的任何东西 → 不做（§11 明写不防，多出来的防护算失败）。
- `/admin` 的写动作（设 PIN / 建档 / 删档）→ ⑤。
- §7.4 的分片按需加载、§8.3 的 `content-visibility`：触发条件写死在 §7.4，④ 不提前实现。

## 12. 测试与验收（§13 的增量）

1. 缓存键三维：`home` 变则两次渲染不共用一条缓存条目（条目数可观察；ETag 差要等 §5 的横幅进页面才成立，所以那里再补一条形状钉）、`profile.json` 内容变则 ETag 变（含 mtime 不动的那种）、
   `q` 不写缓存但同一 `q` 两次渲染 ETag 相同（且不同 `q` 绝不互相命中）。
2. 横幅三条 DOM 断言（§5）。
3. `/switch` 三态各一条；外加"非管理员在别人的档案里伪造 `to=` 跳第三个"必须被拒（§6.1 那句话的证人）。
4. `/prefs`：合法值改写落盘并回读一致；非法值 422 点名字段；两字段都缺 422；令牌与无会话都
   按 §2 的映射答 303 回选择页**且盘上不变**（判据是磁盘，不是状态码）；坏 `profile.json` → 503；**改主题后紧接一次 `GET /` 的 HTML 必须带上新 `data-theme`**（这条
   就是 §1 那个配对的证人，删掉 `profFingerprint` 那一维它必红）。
5. `/admin`：非管理员 303、管理员 200 且表里没有条目内容。
6. **PIN 输错仍然是"回选择页 + `?err=` 提示"，不是裸 303**——这条是 §2 那条区分的证人：把
   `handlePin` 的失败也"统一"成 303 的改动必须被它拦住。
7. 三条新路由（`/prefs`、`/switch`、`/admin`）过既有契约闸（`routes()` ↔ `openapi.json` ↔
   `AGENTS.md`），不需要放宽任何一条豁免。
