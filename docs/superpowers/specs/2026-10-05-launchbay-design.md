替代 NAS 上的 [soulteary/docker-flare](https://github.com/soulteary/docker-flare) 书签导航页。

三条硬指标：**AI 能轻松编辑书签**、**界面好看且打开迅速**、**家里每人一套自己的书签，互不干扰**。

定位是局域网家庭工具：**方便优先，安全做到"不顺手看到、不误改、不泄进仓库"这一档就够，不追求访问控制强度**（§11 有明确的弱化清单）。

## 1. 目标与非目标

目标

- 浏览器标签常驻使用，每天高频打开 → 首屏必须快，NAS 不可用时仍能浏览。
- 书签的增删改既能在页面上顺手做，也能由 AI agent 成批做；改动有历史可查、能恢复到某一次之前。
- 每人一个档案，各存各的数据，互不干扰。管理员就是家长，能进任何档案改东西、能给任何人设 PIN。
- 从 flare 现有配置零丢失迁移，迁移过程可对账。

非目标（明确不做，实施时不得扩张）

- 不做账号体系。没有注册、找回密码、邮箱、权限矩阵。「档案」= 一个名字 + 一个 PIN + 一个目录。
- **不承诺对管理员保密。** 管理员（家长）可以进任何档案看和改。档案隔离防的是互相顺手看到与误改，不是访问控制边界。
- 不做严格安全机制。清单见 §11：不做 cookie 签名、不做 PIN 爆破退避、不做密钥轮换。局域网内任何一台设备本来就能伪造身份，装样子只会增加复杂度。
- 不做档案间共享层、引用层、继承。~~隔离的重复维护代价用「模板克隆 + 补缺」补偿（§4.5）。~~ **2026-10-10 改判**：模板整条拆掉之后这个补偿办法不存在了，于是那份重复维护的代价**是明知的、不补偿的**——每个档案自己存一份，改一处要改 N 处。用户拍板时选了这份代价：共享要有 opt-in 与冲突判据，而本案连共享都不做（见 §4.5）。
- 不做浏览器原生书签同步。
- 不抓取网页正文/不做稍后读。只存链接与元信息。
- 不做原生移动 app。手机用浏览器。
- 不做界面 i18n 框架。界面文案中文；README 双语是仓库层面的事。
- 不暴露公网、不做反向代理与 TLS 终结（那是 NAS 上 Nginx Proxy Manager 的活）。
- 不内建 LLM 调用。"AI 编辑"指 AI 通过外部通路调用写接口，不是网站自带聊天框。
- 不做家长控制（不由家长限定某档案能看到哪些条目）。

## 3. 架构

```
浏览器 ──GET /──▶ Go 服务 ──按 cookie 里的档案──▶ 渲染 ──▶ index.html（内联数据 + 图标 + CSS）
   │                                                        ▲
   │ 写：POST /api/v1/batch（令牌带档案作用域 / 浏览器会话）   │ 读：该档案 bookmarks.json
   └─▶ 校验 → 快照 → 原子写 bookmarks.json → rev+1 ──────────┘

bookmarklet ──?add=<url>──▶ 页面浮层 ──同一写接口──┐
浏览器扩展 ────────────────────────────────────────┤  落到「当前档案」
AI agent（我）── curl / REST ───────────────────────┘
```

## 4. 数据模型

### 4.1 目录布局

```
data/
  profiles/<id>/
    profile.json      # 名字、PIN 哈希、admin 标记、显示偏好
    bookmarks.json    # 该人的书签（服务端可写）
    usage.json        # 点击计数、最近使用（前端节流批量经 /api/v1/usage 上报）
    snapshots/        # 写前快照，保留 50 份，目录名 = rev，内含该 rev 的 bookmarks.json 副本
~~  templates/nas.json  # 建档模板（不参与渲染）~~ **2026-10-10 删**：这一行与整个 `templates/` 目录都不再存在
  icons/              # favicon 内容寻址缓存 + index.json（origin → 缓存项与失败冷却）；站级共享，不随档案切分，§5
  history.jsonl       # 全局逐条动作记录，每行带 profile 与 actor
```

渲染一个页面只读 `profiles/<id>/` 一个目录，代码里不存在"跨档案合并"这条路径 —— 这是不串号的结构性保证。唯一例外是 `icons/`：里面只有按内容哈希命名的图片字节与 `origin → 哈希` 的索引，没有档案 id、没有姓名、没有书签 URL，任何档案渲染 `auto` 项时读到的都是同一份站级缓存（§5 明写它不随档案切分），所以它不构成跨档案信息通道。

### 4.2 `profile.json`

```json
{ "id": "dad", "title": "爸爸", "admin": true,
  "pin": "sha256$8f2a1c$e3b7...", "createdAt": "2026-10-05T12:00:00+08:00",
  "theme": "auto", "layout": "sidebar" }
```

`pin` 是 `算法$盐$十六进制摘要`。**定位是方便**：局域网内想冒充谁改一下 cookie 就行，所以这一层不阻止任何人，只是让共用的设备上"看别人那一套"需要一个口令。实现时不要顺手加登录限速、锁定、签名 cookie —— 那是 §1 明确不做的。

`admin: true` 只出现在一个档案上（家里第一个）。管理员多出三个能力：切换到任何档案、建/删档案、给任何档案设 PIN。管理员进别人档案时页面顶部显示管理横幅，且动作进历史时带 `actor`。

### 4.3 `bookmarks.json`

```json
{
  "rev": 17,
  "groups": [
    { "id": "pinned", "title": "置顶应用", "layout": "tiles",
      "items": [
        { "id": "github", "name": "GitHub", "url": "https://github.com/",
          "icon": "simple-icons:github", "desc": "365 系列", "alias": ["gh"],
          "tags": ["代码"], "order": 1, "aiNote": "" }
      ] },
    { "id": "nas", "title": "NAS 应用", "layout": "list", "items": [] }
  ],
  "search": { "enabled": true, "default": "g",
    "engines": [{ "prefix": "g", "name": "Google", "url": "https://www.google.com/search?q=%s" }] },
  "weather": { "enabled": false, "location": "上海市" },
  "openInNewTab": false, "clock": false, "footer": "", "title": "发射台"
}
```

字段约定

- `groups` 与 `items` 是数组，顺序即显示顺序（`order` 字段与数组顺序二选一——实施时**只用数组顺序**，`order` 字段不写进文件，避免两个真相打架）。
- `id` 全局稳定、ASCII、不许复用；寻址全靠它（§4.4）。
- `icon` 是 `<prefix>:<name>` 或 `auto`；缺省走首字母兜底。
- `aiNote` 只给 AI 看的上下文，界面不渲染。
- 没有 `site:` 段了 —— 全局配置和档案偏好合并进这一个文件 + `profile.json`，谁的文件谁说了算。

JSON 写出契约（不遵守会让 AI 与人的 diff 整片乱跳）

- 缩进 2 空格，文件末尾保留换行。
- `SetEscapeHTML(false)`：Go 默认把 `<` `>` `&` 转成 `\u003c`，书签标题里的 `&` 一多，每次写都污染 diff。
- 键顺序由 struct 字段顺序决定，不许用 map 遍历（map 顺序随机）。
- 非 ASCII 原样输出，中文不许转 `\uXXXX`。
- 空数组写 `[]` 不写 `null`。

### 4.4 写操作与 ops

一次写入 = 一批 ops，**全成或全败**，落到同一个新 `rev`。

路径文法：`groups/<groupId>[/items[/<itemId>]][/<field>]`。寻址只用 `id`，**不用数组下标**——插入一条之后下标会指错条目，这是并发编辑最容易踩的错。

`op` 只有四种：`add`（带 `value`，可带 `index`）、`remove`、`set`（改一个字段）、`move`（`to` + `index`）。不给整表替换型 op（AI 一次换整表会把别人的并发写入抹掉）。

写入流程：该档案进程内互斥锁 → schema 校验 → 把当前文件复制进 `snapshots/<rev>/` → 应用 ops → `SetEscapeHTML(false)` 编码 → 写临时文件 + `rename` → `rev+1` → 追加一行 `history.jsonl`。互斥锁只罩得住进程内，而 CLI 子命令是另一个进程——所以**所有写路径一律收敛到服务进程**，CLI 只经 REST 进来（§4.5）。

冲突控制：请求可带 `expectedRev`，与服务端不符返回 `409 {currentRev}`，调用方重读后重试。这一条留着是因为 bookmarklet 和我的批量整理可能同时写，成本一个字段判断，能省掉整类丢更新。

### 4.5 ~~模板克隆与补缺~~（**2026-10-10 整条拆掉**）

~~隔离的已知代价：Portainer、WireGuard、群晖 DSM 这类家庭服务，每人存一份，改一处要改 N 处。补偿办法只有两条，都不引入引用关系：~~

~~**建档即克隆**~~ 与 ~~**`sync-template`**~~ —— **2026-10-10 整条拆掉**：每个档案完全分离，建出来时形状一模一样，没有一份共用的东西可以被复制给谁，也没有"把一份清单推进各个档案"这件事可做。建档就是建档；要往档案里加东西只有两条路——本人自己加，或从浏览器导入（导入也只进某一个档案）。
  - 不做字段级三方合并、不存"上次同步基线"。那需要第三份状态，而这个场景里"报告冲突让人挑"比"自动合并"便宜且不会猜错。

CLI 子命令（`profile create` / `revert` / `import-bookmarks`）**不直接写盘**：以容器 env 里的令牌调本机 REST——`profile create` 走 `POST /api/v1/profiles`，`revert` 与 `import-bookmarks` 用**目标档案自己的**令牌走 `/api/v1/data` + `/api/v1/batch`（`*` 那枚只管账号，不碰内容）。写路径因此只有 store 一条，§4.4 的进程内互斥锁才罩得住；服务没起时 CLI 报错退出，不存在绕过服务直改文件的通路。

那条免凭证的引导建档（`POST /setup`，§8.0）也吃同一条纪律，而且吃的是一半更硬的那半：**判据（磁盘上是不是零档案）与写入同属 store 的一次串行化**（`CreateFirstProfile` 在锁内重查目录数），handler 不许自己数完再决定写不写。按档案 id 的那把锁管不了这件事——两个不同名字各自派生各自的 id，谁也不撞谁，光靠"已存在就拒"会安静地建出**两个**管理员档案。"只在零档案时开着"这句话要在写入那一刻也为真，判据就只能待在写入所在的那个临界区里；两处数会得出两个答案，而"谁有资格当这台盒子的第一个主人"不能有第二个答案的来源。同一条纪律还管着坏档案的出路 `POST /api/v1/profiles/rebuild`（§6.1、§12）：**"这份档案读得动吗"与"要不要覆盖它"必须发生在同一次按 id 的临界区里**。handler 若先自己 `LoadProfile` 看一眼再决定写不写，两次读之间档案被人修好，它就会把一份已经读得动的 `profile.json` 盖掉——那是"改档"的第二份判据，也是这条端点唯一真正的危险。

### 4.6 历史与恢复

- `history.jsonl` 每行：`{at, profile, actor, by, rev, ops: [{op, path}]}`。`by` ∈ `ai | bookmarklet | extension | web | import | cli`（`sync-template` 随模板机制一起没了——没有任何动作再写得出这个值，留在合法集里就是个"看起来还能用"的假选项）。它是调用方自报的口径字段，只用于历史筛选与界面展示，不参与任何权限判定；管理员代管由 `actor` 表达，不占 `by`。`revert` 与改 PIN 这类动作在历史里记成 `ops:[{op:"revert"|"set", path:"snapshots/<rev>"|"profile/pin"}]`，`rev:0` 表示这次动作不产生书签 rev。
- **只存动作与目标 `id`，不存条目内容**：日志不是第二条翻书签的路。要查内容用 `GET /api/v1/history?profile=&limit=`，走档案权限。
- 管理员跨档案的操作在 `actor` 上留名，且这些记录出现在**被管理档案自己的历史视图**里。这条我坚持保留：不花任何额外机制成本，只是把已经记下的数据渲染出来，换来的是"谁动过我的书签"随时可查。
- 恢复：`launchbay revert --profile dad --to 12` 取 `snapshots/12/bookmarks.json` 覆盖当前文件（这本身是一次新写入、产生新 rev，不抹历史）。快照只含 `bookmarks.json`：revert 恢复书签，不动 `profile.json`，主题布局这类偏好不在恢复范围内。

## 5. 图标系统

选型依据（2026-10-05 用 Iconify 集合接口与 npm 下载统计接口实测）：按**真实概念数**排（名义总数会骗人——`material-symbols` 的 15,717 是同一图标三种风格各算一条，`ph` 的 9,072 是六种字重各算一条）：`mdi` 7,447 > `tabler` 6,220 > `material-symbols` ~5,239 > `simple-icons` 3,463（全是品牌）> `ph` ~1,512。npm 月下载 `@tabler/icons` 15.3M 居首。`tabler` 的 `brand-*` 实测 10 缺 9（emby / jellyfin / wireguard / portainer / n8n / syncthing / homeassistant / nginx / plex 全无），所以通用层不能兼任品牌层。

双层：

| 层 | 套 | 许可 | 用途 |
|---|---|---|---|
| 品牌层 | `simple-icons` | CC0-1.0 | 有官方 logo 的服务。你 25 个自建服务命中 |
| 通用层 | `tabler` | MIT | 没有品牌 logo 的概念图标（定时任务、证书、弹幕、阅读…） |

渲染规则

- 服务端二进制内嵌两套的 **name → path 索引**。产物由 `tools/genicons`（Go，只用标准库）从 Iconify collection API 生成，**gzip 后提交进仓库**（`internal/icons/index/*.json.gz`），构建期零网络、零 node。产物**只存 `<path>` 的 `d` 字符串与必要时的 `viewBox`，不存上游 SVG 标记**：`<svg>` 的标签、`fill`/`stroke`、`stroke-width` 全由渲染模板决定，`d` 只是属性值——上游 JSON 里的任何东西结构上都变不成 HTML，而 §7.5 那句"磁贴内 `stroke-width` 提到 2.5"也就成了 CSS 而不是文本替换。体积是硬约束（gzip 产物与镜像大小都在计划第 0 步实测，不靠估），超线时的后备阶梯按顺序来，砍到哪一档就停：① 砍 `aliases`（只降级搜索命中，不影响任何渲染）；② 砍 tabler 的 `-filled` / `-alt` 派生变体（同一概念的多形态，本节开头"名义总数会骗人"说的正是这类）；③ 仍破线才考虑把索引移出仓库改构建期生成——那要重新过 §10 的"构建期零 node"决定，属于改判而不是打补丁。
- 上游的 `aliases` 存下来**只用于搜索命中**；`/api/v1/icons` 返回的与落到磁盘的候选永远是规范名——图标在数据里只有一种写法。
- 买到的能力如实收窄一档：AI 运行时新增**快照里存在**的任何图标名都能立刻渲染、不需要重建前端；刷新图标库是"跑一次生成器提交新产物"，不是重新设计前端。代价是快照与上游会漂，漂了的后果是首字母兜底加 `iconUnmatched` 计数（§6.2 明写读路径不因索引漂移进坏档），不是档案打不开。
- 首屏 HTML 只内联**当前档案实际用到的** path（42 条约 10KB），零图片请求，离线全可用。
- 解析失败（名字不存在 / 缺 `icon`）→ 首字母色块兜底，色块取分组 `accent`（合法才用）或名称哈希的色相。缺图数是**读时算**出来的静态差集（`/api/v1/status` 的 `iconUnmatched`），不往 `usage.json` 记事件：缺图是索引与数据的属性而不是行为，记成事件会让 `GET /` 产生写盘副作用，而且索引一刷新，旧记录就成了谎话。口径要收窄：`iconUnmatched` 只数**看着对却查不到的名字**（`<prefix>:<name>` 不在快照里，或 `auto` 且无缓存）；空 `icon` 不算缺——它是"没设"，在 `GET /api/v1/data` 里一眼可见，不需要一个计数器来提醒，而这个计数器存在的理由恰恰是那种静默降级的情况。
- `GET /api/v1/icons?q=<关键词>&prefix=<tabler|simple-icons>&limit=` 在本地索引里搜索。**图标名不许靠猜**——实测 `material-symbols:podcast`、`tabler:podcast` 都不存在，所以 `AGENTS.md` 写明：挑图标前先查这个端点。

favicon 抓取（`icon: auto` 才用，非主力）

内网服务普遍没 favicon 或只有默认图。抓取约束：

1. **只由 `/api/v1/resolve` 触发**（要求凭证：令牌按作用域、会话按当前档案，不给匿名探测接口），不提供独立的"传个 URL 立刻抓图"端点，也不由数据变更派后台抓取任务。如实记录放弃的那半条：AI 绕过 resolve 直接写 `icon: auto` 的条目不会有图，走首字母，直到有人经 resolve 抓过一次——`auto` 本来是非主力，而给服务进程加一套脱离请求路径的后台抓取/重试机制，代价比这几条首字母大。
2. GET、3 秒超时、响应 ≤ 256KB、`Content-Type` 必须是 `image/*`；最多跟随 3 次重定向，非 2xx 即失败不解析。抓页面 HTML 与抓图片共用这组约束。**如实写明超时的形状：3 秒是每一跳各自 3 秒**（每请求现建 Client、重定向由实现自己逐跳跟，整条链没有共享 deadline），最长重定向链合计可到约 12 秒——证人 `internal/icons/fetch_test.go` 的 `TestFetcher_超时预算是每一跳各自的`；另一半天平是单跳内 3 秒覆盖 dial+响应头+正文读取（`TestFetcher_慢正文也算超时` 钉住）。
3. 内网段默认允许（书签本来就是内网服务），不做"关闭私网"开关——局域网工具没有这个需求。
4. 结果按内容哈希落 `data/icons/`（同字节二次抓不落两份），`origin → 缓存项` 的索引也在 `data/icons/` 里，失败按 origin 记 24 小时冷却，冷却期内 resolve 不再抓。对外走 `/icons/<hash>.<ext>` 并 `immutable`（§7.1）；图标缓存是站级共享，不含个人信息，因此不随档案切分。
5. 索引一变就让首屏渲染缓存失效（键见 §7.1）：否则"resolve 刚抓到图，页面却要等下次写入才显示"是句谎话。

| `/api/v1/profiles/rebuild` | POST | 只重写 `profile.json` 的坏档出路。仅管理员（`*` 令牌或管理员会话；档案作用域令牌打它是 403，这是设计不是故障）。体 `{profile, title, admin, pin}`，四格都必须出现。判据在 store 锁内：**读得动 → 409**（改 PIN 请走 `profiles/pin`）；目录不存在 → 404（**这条端点不建目录**，建档案是 `POST /api/v1/profiles` 的事）；只有"内容错"与"文件不在"才允许覆盖，其它读失败原样上报不许盖。写完在同一把锁内回读一次，读不动答 500——"200"意味着进门页那张卡真的回来了。`bookmarks.json`/`snapshots/`/历史已有内容不碰一个字节；历史追一行 `{rev:0, ops:[{op:"set", path:"profile/rebuild"}]}`；`X-LB-By` 头可选，缺省 `web`。`theme`/`layout`/`createdAt` 按默认重建（读不出来就没有"保留"这个选项，明写在 §12） |
| `/healthz` | GET | 存活 |
| `/icons/{name}` | GET | §5 抓来的 favicon 缓存，文件名必须是 `<hex 哈希>.<png\|ico\|svg\|webp\|gif>`；不匹配这个形状直接 404，不做目录解析。公开、`immutable`（§7.1）；一律带 `Content-Security-Policy: sandbox`——第三方字节由本服务自己的 origin 端出，直接被浏览器当文档打开（尤指 svg）时不许有执行能力 |

`POST /api/v1/batch` 请求体：

```json
{ "profile": "dad", "expectedRev": 16, "by": "ai",
  "ops": [ { "op": "add", "path": "groups/nas/items",
    "value": { "id": "jellyfin", "name": "Jellyfin",
               "url": "http://10.0.0.3:8096", "icon": "simple-icons:jellyfin" } } ] }
```

响应：成功 `200 {profile, rev, applied, warnings[]}`；校验失败 `422 {errors: [{opsIndex, field, reason}]}`；rev 冲突 `409 {currentRev}`；无凭证 `401`；作用域不含该档案 `403`；档案不存在 `404`。

`resolve` 供两处共用：添加浮层的自动补全，和我加书签时的信息补齐。同一份实现，避免"页面能自动填、AI 拿不到"的分裂。它只取 `<title>` 与 `og:description`，不存正文、不留抓到的 HTML，复用 §5 的超时/大小/重定向约束。添加浮层走会话即可，家里人零配置（§6.3）。建议分组只从**该档案现有分组**里打分选（同 host、同首标签、分组 id 或标题出现在 URL 与名字里），选不出就返回 `null`，不凭空造分组；候选图标只在本地索引里搜（品牌层优先），给的永远是规范名——图标名不许靠猜这条对 `resolve` 自己同样成立。

### 6.2 校验先于落盘

ops 在写文件前整体过 schema：`id` 唯一、URL 只拒三种情形（空、无法解析、缺主机名）而**不按协议设白名单**、目标分组存在、`icon` 名在本地索引内、`index` 是合法整数、字段类型正确。**任一条失败整批拒绝**，并逐条回报错在哪条 op 的哪个字段。

> **2026-10-12 局部改判：`file:` 不在"缺主机名"那一档里。**
> 上面那句"缺主机名就拒"会让 `file:///D:/Downloads/x.html` 整条进不来——它的 Host
> 恒为空，因为那台"机器"就是本机。实测的后果是**一个人存了十年的本地网页收藏整份导
> 不进来**（报告说"读出了书签，但没有一条能进来"）。于是 `model.CheckURL` 给 `file:`
> 单独一格：**路径非空就算一条真地址**。
>
> 其余无主机名的协议仍然拒：`javascript:` 与 `data:` 带的是脚本与数据，点一下就在书签
> 页里执行；`mailto:`/`tel:` 是动作不是目的地。放行它们换来的不是"限制少一点"。
>
> 放行之后**代价由渲染层那一格接住**（§6.2 的后半句没有变）：`ExternalScheme` 只认
> http/https，所以本地文件标「需手动打开」——浏览器确实禁止从 http 页面跳 file:。
> 图标那条路对非 http 直接返回空串，不会去读本机文件。
>
> 下面 2026-10-10 那段把 `file:` 与 `javascript:`/`data:` 并列成"没有主机名的地址"，
> 按今天的判据只对后两者成立。

**2026-10-10 局部改判：导入这条路"先挑出去再写"，写路径的整批拒绝原样不动。**
这一节那句整批拒绝的**理由**是"AI 一次改 30 条时，改坏一半比全没改难收拾"——它假定的
调用方是**一次提交一批、内容由自己写的**那个人。而浏览器收藏夹导入不是这个形状：源文件
是用户几十年的收藏，里面混着 `javascript:`、`data:`、`file:` 这类没有主机名的地址是
**常态**，让一条书签小工具把另外两百条挡在门外才是 bug（实测就是这条：一份真实导出
上来就报"有 6 条过不了校验，整批没有写入"）。所以 §9 的导入器改成**用同一份判据
（`model.CheckURL`）先逐条挑出进不来的、在报告里逐条点名，然后用剩下的生成 ops**——
batch 拿到的是一批本来就合法的 op，整批拒绝在它身上不会再触发。判据仍然只有一份，
写成两份就会漂。

改判的另一半：**id 的长度预算是导入器的义务，不是 batch 的**。真实导出的文件夹名动辄
三四十字符，`分组id-书签名` 拼出来必然破 `ValidSlug` 的 32——那是导入器自己造出来的
非法值（每一条都非法，于是每一条都被拒），必须截，不能指望下游放宽。

`icon` 名在索引内这一条**只卡写路径**（由 ops 层拿着图标索引逐条查，报成 `opsIndex` 指对那条 op 的 `field: "icon"`），`model.Validate` 不查索引。理由：索引是某一刻抓的冻结快照（§5），而 `model.Validate` 同时跑在读路径——把索引绑进读路径，等于让"快照与磁盘不同步"这种必然会发生的事把家里人的档案打成坏档；§12 的坏档隔离是给数据文件真损坏用的，不该被索引漂移触发。后果就是想要的这一条：写进去的名字保证能渲染，磁盘上已有的陌生名字照样读、走首字母兜底、进 `iconUnmatched` 计数。

URL 协议为什么不设白名单：真实数据里就有 `chrome://extensions/` 这类条目（§9 要求原样保留），拒存等于替用户偷偷删书签。协议是否可跳转交给渲染层判断——`model.ExternalScheme` 为真时界面标「需手动打开」并给出地址，不渲染成 `href`（浏览器从网页跳 `chrome://` 会静默失败，那比不给链接更坏）。

理由：AI 一次改 30 条时，"改坏一半"比"全没改"难收拾得多。

### 6.3 令牌与 bookmarklet

管理员**另有一把机器级的 key**，与这份列表无关：

```
LAUNCHBAY_ADMIN_TOKEN=zzz
LAUNCHBAY_WRITE_TOKENS=ai-dad:xxx:dad,ext-dad:yyy:dad
```

- 每个客户端一个命名令牌 → 某一端泄露单独吊销，不必全换。
- 常量时间比较；令牌只从 env 读，不进配置文件、不进日志。
- 配置串里有空条目或尾随逗号**一律拒绝启动**，不许静默跳过：跳过一个坏条目等于留下一个操作员以为存在、却永远 401 的客户端，比启动失败难查得多。
- **整串为空是合法配置**（2026-10-12）：这台机器不发档案作用域令牌，服务照常起。硬性要求它等于让每个装机的人都得填一个、再把它留成一个公开的默认值——那份默认值恰好能写最常见的档案 id。要令牌的是浏览器扩展、CLI 与 AI 脚本，而那三样本来就要人主动去装。**管理员那把 key 才是必填的**：缺了它，建档与删档就没有人能做到。
- **bookmarklet 与页面浮层零令牌**：bookmarklet 只做一件事 `http://<NAS_IP>:7600/?add=<当前URL>&t=<标题>`，打开的是同源导航页，写走会话 cookie——家里人不需要在任何地方配令牌。令牌只发给 AI（REST）、浏览器扩展（P2，`chrome.storage.local`）和 CLI 子命令（读容器 env 里的管理员 key，§4.5）。Chrome 书签会云同步，令牌写进任何书签 URL 等于明文外发——这条铁律不因浮层无令牌化而放松。
- 管理员**不再依附于任何档案**（2026-10-12，见本节上方的注记）：`profile.json` 里没有 `admin` 字段，"第一个档案自动是管理员"这条规则随之消失。浏览器那边进管理页靠 `POST /admin/login` 交一次 key，服务端发一条 `lb_admin` cookie（装的是 HMAC 派生值，不是 key 本身）。

### 6.4 `AGENTS.md`

仓库根一份给 AI 读的契约：令牌从哪个 env 拿、**令牌作用域决定能写哪个档案**、端点清单与示例 ops、"改完必须 `GET /api/v1/data` 复核"、"挑图标前必须查 `/api/v1/icons`"、"JSON 写出必须遵守 §4.3 的写出契约"、禁止事项（不许直接改 `data/` 下文件、不许把真实档案目录提交进仓库、不许跑导入的写入那一步除非我明确要求）。

不提供 MCP server：REST + curl 已够用，少一个常驻件。

顺带写明一件会让 AI 复审时误判成 bug 的事：`/api/v1/status` 与 `/api/v1/profiles*` 是跨档案端点，**要管理员令牌**；档案作用域的令牌拿它们会 403，这是设计不是故障。查单档案状态请用 `GET /api/v1/data`（含 `rev` 与条目）。

## 7. 前端与性能

### 7.1 渲染与缓存

| 资源 | 头 | 理由 |
|---|---|---|
| `/`（HTML） | 含书签的档案首屏：`private, no-cache` + 内容 `ETag`；**无 cookie 的进门页三形状：`private, no-store` 且不发 ETag**（§8.0） | 前者改了必须立刻看见、304 时零传输；后者整页是跨档案的名单，缓存住等于把全家名字留给下一个共用这台电脑的人（§7.1 末条），给它 ETag 还会让浏览器拿它去 revalidate 一个本不该留副本的页面 |
| `/api/v1/*` | `private, no-store` | 会话相关读接口一律不缓存 |
| `/*.<hash>.css\|js` | `public, max-age=31536000, immutable` | 文件名带指纹 |
| `/icons/*` | `public, max-age=31536000, immutable` | favicon 按内容哈希命名，不进 SW 预缓存清单，运行时 cache-first |

**串号（爸爸手机上出现妈妈的书签）是这套设计最贵的一类 bug**，所以键里处处带档案：

- 渲染内存缓存键 = `(profileId, home, homeFingerprint, rev, bookmarksMtime, profileFingerprint, iconGen)`，不是单独的 `rev`（两个档案 rev 恰好相等是常事）。`bookmarksMtime` 让外部程序改盘也能失效重算（§12 最后一条）；`profileFingerprint` 是 `profile.json` 的**内容**指纹（不是它的 mtime：Linux 的 tmpfs/overlayfs 与 CIFS/9p 挂载能把时间戳粒度粗到“写完立刻 stat 还是旧值”，P1-④ 验收实测过两次原子替换的 mtime 纳秒级相同），主题与档案形态存在那里，缺这一维或只认时间戳，都是按钮按下去没反应（P1-④）；`home` 是管理横幅那一维：横幅取决于 `lb_home`，而页面渲染的是 `lb_profile` 的书签，缺这一维会把"带横幅的页面"缓存给被管理的本人看到，正是串号；~~这一维随代管态一起作废（2026-10-10：横幅不存在了，键里那一位也删了——留着它等于为一个不存在的形状占着键位）~~；`iconGen` 是 favicon 缓存的代次计数：`data/icons/` 一变化就让页面重算，否则刚抓到的图标要等下次写入才显示。带 `?q=` 的请求**不进这个缓存**（否则键空间随击键膨胀），但照样发 ETag。
- `ETag` 由 `(profileId, rev, 内容哈希)` 算出，跨档案不得相同。
- SW 的 HTML 缓存名 = `html-<profileId>`；无 cookie 时只允许命中 `html-picker`。
- 三条各配单测，外加 §13 的双档案离线端到端回归。

Service Worker 策略

- 预缓存清单由构建生成（壳、CSS、JS、静态图标）。
- SW 读不到 cookie（fetch 事件里的 `request.headers` 不含 `Cookie`），所以它自己无法选档案。HTML 响应统一带 `X-LB-Profile: <id|picker|-admin>`。这两个哨兵值对应的页面都是 no-store——SW 根本不为它们分桶，这才是防线本体；`-admin` 取 `model.ValidSlug` 拒收的形状，是给**将来新加**的哨兵定的规矩（`picker` 这个词与 `/switch` 的 `to=picker` 共享词汇，P1-① 就写进了契约，不改）。，SW 按它决定**存入**哪个 `html-<id>`；同时把这个 id 记进 IndexedDB 的一条 `currentProfile` 记录。离线**回退**时按这条记录取对应缓存；记录不存在（本设备从没成功在线过）一律回退 `html-picker`。切档与退出时同步改写这条记录并清掉旧档案缓存（§7.1 末条），两个动作必须同批做，否则缓存与记录会指向不同档案。
- **HTML 走 network-first**，超时 1.5 秒回退缓存：LAN 里网络几乎总通，所以"永远最新"；NAS 挂了才吃缓存。这条专门对付"SW 把含数据的 HTML 缓存住导致看到旧书签"。
- 检测到 `rev` 变化时不静默 `skipWaiting`，顶栏出「书签已更新，点刷新」。
- **切换档案时清掉上一个档案的 HTML 缓存**。共用设备上离线残留别人书签算泄露，各人自己设备不受影响。

### 7.2 首屏构成

`index.html` = 内联 CSS + 内联 SVG path（仅用到的）+ 完整书签 DOM + 一个 `<script type=module defer src=/app.<hash>.js>`。**关掉 JavaScript 时全部书签仍可见、可点**——这是"内联首屏"的验收判据，不是修辞。

### 7.3 性能预算（CI 实测，超线即红）

- 首屏 HTML gzip ≤ 120KB
- CSS 内联 ≤ 40KB（压缩后）
- JS ≤ 128KB gzip（**2026-10-16 改判**：原 60KB，见下）
- LAN 首屏 LCP < 300ms
- SW 命中时二次打开 < 50ms，除 HTML 文档本身（network-first 必发一次）外零网络请求
- 1,000 条滚动 ≥ 55fps

**JS 那一条为什么从 60KB 改到 128KB（2026-10-16）**：这一天里三件事各自合法地把脚本
撑过了原线——书签栏/地址栏拖入并就地落位（`spliceCardIn`：抓一次服务端片段、只接
那一行、用 FLIP 让它从松手处滑进格子）、排序与拖入共用的那套动效、图标库打开时先摆
这一份已在用的图标。当天实测 **gzip 65.4KB**，而原线只剩 51 字节——「线剩几十字节」与
「线还差 400 字节」是同一件事：它已经不再是"涨到两倍时有人看一眼"，而是**下一个功能
必须先来求人**。

128KB 就是那个"两倍"（65.4 × 2 ≈ 131KB，取 128 这个整数），与 CSS 那条
「2 倍余量」同一个标准。**决定人：用户**（2026-10-16 被问"要腾字节还是拍板抬线"时选了抬）。
`internal/render/budget_test.go` 那边拆成了两档并各判一次：操作线 125,000（先响）与
这一条契约 131,072（外层硬顶），**读数与决定都记在那个文件的注释里**。

落点（P1-④ 定）：**字节类三条（HTML gzip / 内联 CSS / JS）进 `go test`**，直接量渲染产物，
**不加 gzip 中间件**（局域网里那点字节换不回一次往返的时间，却要让每个响应都想清楚
Content-Encoding 与 ETag 怎么相处）；零 JS 的阶段，"`<script` 计数为 0"是一条真断言。
**LCP、帧率、SW 命中这三条要真浏览器与真网络的数不进 CI**：
headless 的默认值陷阱已经实测过（`prefers-reduced-motion` 默认报 `reduce`，六张主图差点全拍成
动效关闭态），假闸比没闸贵——它们留在 §13 的人工实拍清单里，写清怎么测。

**CI 组成（2026-10-09 改判，理由见下）**：两条 workflow。

`ci.yml`——`ubuntu` 上四道门禁 + 预算测试 + 泄漏守卫 + **依赖守卫**，`windows` 矩阵只跑门禁与测试（不跑工具类守卫），外加一个**只 build 不推任何东西**的镜像 job。

`docker.yml`——**发布**：main 推送、打 `v*` tag 或手动触发时，用 buildx 构建 `linux/amd64` + `linux/arm64` 并**双推 Docker Hub 与 GHCR**，tag 由 `docker-compose.yml` 里的 image 版本号派生（`x.y.z` / `x.y` / `x` / `latest` / `sha-<短>`）。

改的是四条，判据与"假闸比没闸贵"不冲突——每一条的判据都能在本机一次跑完、失败信息能指到具体文件，且都不是"需要一个 headless 浏览器才拿得到数"那一类：

1. **依赖守卫（`tools/depguard`）**：本仓库是**零外部依赖**的纯标准库程序（`go.mod` 只有
   `module` 与 `go` 两行）。这是它最大的安全属性——没有 CVE 面、没有供应链、没有
   `go.sum` 可漂移。但它当时**没有任何东西守着**：一句 `go get` 就能把依赖引进仓，
   CI 一声不响，而这个属性是整个 §11 安全取舍的地基。守卫的判据是 `go list -m all`
   只列主模块一行、`go.sum` 不存在或为空、`go.mod` 里没有 `replace`/`exclude`/`retract`
   ——三条都只看仓库自己的文件，不需要网络。
2. **windows 矩阵**：本机是 Windows，而路径正是这块代码的已知痛点（P1-④.6 的计划里
   专门把绝对路径换成 `git rev-parse`，就是目录改过名之后那些命令会静默失效）。
   `internal/store` 读写真实文件、`.gitattributes` 管着 `eol=lf`、产物按 `*.json.gz binary`
   提交——这些在 ubuntu 上全绿过一次，不等于在 Windows 上也成立。
3. **镜像 job**：Dockerfile 里那句"门禁在镜像构建里跑一遍：CI 绿不代表这个镜像可用"
   从来没被 CI 验过。`golang:1.27-alpine` 是否还在、`COPY` 的路径是否腐坏、`scratch`
   里缺了什么，只有真构建一次才知道。它不跑应用测试（Dockerfile 内部已经跑过一遍），
   只 build 到一个不推送的 tag，所以成本约等于一次 `go build`。
4. **发布 workflow（`docker.yml`）**：自托管项目的镜像要能被别人 `docker pull` 到
   才有分发，buildx 出多架构清单（树莓派与 ARM 群晖是这个品类真正会跑上去的机器），
   双推 Docker Hub 与 GHCR 让两个习惯都成立。**版本号取自 `docker-compose.yml` 的
   image tag 而不是 git tag**：那是部署实际引用的那一份，两处只能有一个来源——打了
   tag 却忘了改 compose 是同一个 bug 的两个方向。取不到就**报错**，不静默退化成
   "只有 latest"。它不在门禁链上（推镜像不是判据），但它推的是**刚跑过门禁的代码**
   （Dockerfile 的 amd64 那一路里带 `vet` 与 `test`，构建失败则 push 根本不会发生）。

仍然**不进 CI** 的：LCP / 帧率 / SW 命中（要真浏览器 + 真网络），以及任何需要人工
判断的"这看着对不对"。

### 7.4 规模降级（写进文档，不提前实现）

条目 > 300 且预算破了，才切成"首屏内联前 N 组 + 其余走 `/data.<rev>.json` 分片按需加载"。当前 42 条不需要。触发条件写死在这里，是为了防止"反正都支持"式的提前实现。

### 7.5 可访问性

- 焦点可见：所有可交互元素有可见焦点环，暗色下调亮色环（对比度算出来，不靠肉眼）。
- 图标 `<svg aria-hidden>` + 相邻文本承载可及名；分组标题用 `h2`/`h3` 成结构。
- 触摸目标 ≥ 44px；磁贴内图标渲染尺寸下限 20px（tabler 是 2px 线条，小于此会在渐变底上糊掉，磁贴内 `stroke-width` 提到 2.5）。
- `prefers-reduced-motion: reduce` → 关极光漂移、stagger、抬升，只留透明度。
- `prefers-color-scheme` 驱动暗/亮；`forced-colors` 下去掉毛玻璃与阴影、保留边框。
- 键盘：`⌘/Ctrl K` 开面板，`/` 聚焦搜索，`n` 开添加浮层，`?` 快捷键帮助，`↑↓` 选择，`⌘/Ctrl ↵` 后台标签打开（家里混用 Mac 与 Windows，双轨写死）。

## 8. UI 规格

风格：**极光玻璃**——暗色默认，亮色派生（`profile.theme: auto` 跟随系统）。

- 背景：三层径向渐变 + 46px 模糊 + 16 秒缓慢漂移；叠一层 3px 网点纹理。

界面清单

0. **进门页**（无 cookie 首屏）三形状，判据是 `profiles/` 下的**目录数**（坏档案也占位，所以不是"有几个读得动的档案"）：**0 个** → 引导建档表单（`POST /setup`，名字 + PIN，建成即管理员，成功不发会话）；**1 个** → 直接是那个人的进门页（h1 就是他的名字，不再问「谁来用？」）；**≥2 个** → 一排档案卡（首字母头像 + 名字 + 每张卡自带的 PIN 输入），带 `?add=` 进来的穿过 PIN 步骤不丢。整页零条目、零 URL、零分组名；三种形状都 no-store。**一份都进不去时要点名**：卡片列不出来（profile.json 读不动，或目录里根本没有它）时这一页不许只剩一个空列表——读得动的照常给卡，读不动的那些各占一行给 `id` 与「数据文件读不了」（只能给 id：标题就住在那个读不动的文件里，编一个是假话），一份都点不出名时只给那句总的。这一支**不改判据**：目录数仍是唯一判据，所以"把一个档案装坏了"永远不开引导窗口（§11 记的那件事）。产品里没有页面内的修法，那一行因此只说"要在这台机器上修好那个文件"，不给按下去没反应的东西。**"多用户"不是配置项**——没有 `LAUNCHBAY_MULTI_USER`，没有档案里的模式字段；建了第二个档案才是多人，删到只剩一个就退回单人。

## 9. 浏览器书签导入与对账

**输入**：浏览器导出的 **Netscape 书签 HTML**（`<!DOCTYPE NETSCAPE-Bookmark-file-1>` 开头）。
Chrome / Edge / Firefox / Safari 都能导出这一个格式，所以**一个解析器覆盖全部**。
它长得像 HTML 但不是合法 HTML（`<DT>` 不闭合、`<DL><p>` 后面跟着多余的 `<p>`），
所以用 `internal/bookimport` 里手写的扫描器，只认 `<DL>` `<DT>` `<H3>` `<A>` `<DD>` 五个标签。

**入口**：`launchbay import-bookmarks --profile <id> [--dry-run] <bookmarks.html>`。

**落点分两条通路，分工是这一节的要点**：

- **书签本体走 `POST /api/v1/batch`**。快照、历史、rev 递增都发生在 batch 内部，
  绕过它等于造出第二份真相（§11 与 AGENTS.md 禁止事项第一条）。导入器只负责生成 ops。
- ~~**模板写成当前目录下的一个文件**，人看过再拷进 `data/templates/`。模板不参与渲染、
  不产生 rev、也不进历史，没有"绕过谁"的问题；而"别人的档案克隆起步时拿到哪几条
  内网服务"是一次值得人过一眼的决定。走 `store.WriteJSON` 写，与服务端逐字节一致。~~
  **2026-10-10 删**：模板整条拆掉，这第二条通路没有了——导入只有"写进某一个档案"
  这一个去向。

**目标档案必须是空的**：导入的语义是"把浏览器那套导进来"，不是往现有档案上叠加。
对着已装了几十条的档案跑一遍，那几条会无声消失——撞上了报错让人自己选。

**进不来的条目：跳过 + 逐条点名（2026-10-10）**
`POST /api/v1/batch` 的"整批拒绝"没有因为这条而放宽（§6.2 那一段的局部改判说清了理由），
改的是导入器**在生成 ops 之前**先过一遍同一份判据（`model.CheckURL`，判据一份不抄）：

- 地址要有主机名。`javascript:`、`data:`、`file:` 因此进不来；`chrome://extensions/`
  有主机名，按 §6.2 原样保留（渲染层给「需手动打开」角标）。
- 空名字的书签同样挑出去（`model` 的 name 判据也不许空，两条拼起来才判得全）。
- 挑出去的那些**逐条点名地址与理由**进报告的「## 没能进来」一节，不静默丢；网页摘要
  与 `/api/v1/import` 的响应都另外给一个**跳过条数**（`skipped`），因为只说"会加 N 条"
  会让人以为文件里就这么多书签。
- **筛完一条都不剩的文件夹不建**，但要点名——侧栏上一个点进去空无一物的文件夹只会
  让人以为导漏了。
- **整份文件一条都进不来是另一个形状**：说"读出了书签，但没有一条能进来"，不说成
  "文件里没书签"——后者会把人引去换一个同样导不进来的文件。
- 判据只管**能不能写**；被挑出去的条目**不进对账的源**。理由同回收站那一条：一条永远
  红的对账会让人把判据调松，调松之后真正丢的东西就跟着看不见了。它们另有去处——
  「## 没能进来」那一节。

**id 的长度预算是导入器的义务**：分组与条目 id 都要满足 `ValidSlug` 的 32 字符上限。
`分组id-书签名` 这种拼法在真实导出上必然破限（文件夹名三四十字符 + 长书签名 = 46），
于是按预算截：书签名截到 `32 − len(分组id) − 1`，依次退化到 URL slug、再退化到 `item`；
唯一性按**整个档案**判（`model` 的 id 唯一是全档案级），撞了递加后缀且**递加后重新截断**
（不重截的话去重反而会造出更长的非法 id）。

映射

| 浏览器书签 | launchbay |
|---|---|
| `<H3>` 文件夹 | 一个分组。**嵌套被拍平成顶层**，路径拼进标题（"常用工具 / 同步"）——§4.3 的分组没有父子关系，硬造一层就得在 id 里编码路径，于是改名成了改 id，而 id 一变别人的链接就断了 |
| 顶层没有文件夹的 `<A>` | 归进一个合成的「书签栏」分组，`layout: tiles` |
| `<A HREF>` 的文字 | `name` |
| `<A HREF="...">` | `url` |
| `<DD>` | `desc`（同一条有第二个 `<DD>` 时留第一条并记账） |
| favicon | **不导**。浏览器导出的书签只有 favicon、没有图标名，改为按网址猜（见下） |

**回收站不进档案**：`<H3>` 名为「回收站」/「垃圾桶」/`Trash` 等的子树**从树上摘掉**
（`tree.Trashed`），不进分组。它们也被排除在对账的源之外——早先把它们并进源去"涵盖"，
结果是每次导入都必然报"丢了 N 条"，而那 N 条是有意不导的；一条永远红的对账会让人
把判据调松，调松之后真正丢的东西就跟着看不见了。

图标

浏览器导出的书签**没有图标名**，所以按网址猜：`internal/icons.Candidates` 的 token 顺序
（主机段 → 路径段 → 标题词）拿去做**完整键精确匹配**（`ix.Has`）。

**这里刻意不用 `Candidates` 的模糊匹配**——那个是给添加浮层用的（返回 5 条给人挑），
而导入是自动落库、没有人在旁边挑，"取第一条"等于取一个模糊结果。实测症状很具体：
`chrome://extensions/` 会猜出 `simple-icons:gitextensions`（路径段包含匹配）。
猜不到就**置空走首字母兜底**并列入报告的"想补图标"清单，**不配一个形似的图标顶上**——
后者会让这批书签看上去都有图标，直到有人逐条点开才发现全是错的。
非 http/https 的地址压根不猜，也**不计入缺口清单**（它在浏览器里点不动，配图标没意义）。
`internal/bookimport/icons.json` 是可选的手工覆盖表（`{"host": "图标名"}`），
每一项都对索引校验，写错就中止导入。

对账口径（三条全过才算导完）

1. 条目数相等（**按 URL 配对**，不是按 (URL, name)：用 name 一起当键的话，改名会配不上，
   于是报成"丢了 A、凭空多出 A改名了"，把一次改名说成丢失加增生）
2. 逐 URL 差集为空
3. `name` / `desc` 逐条比对；图标**不参与**——源里本来就没有图标名，它是猜的，
   那是允许的整理动作，记进逐条明细而不是判红

导入报告逐条点名：解析时跳过的每一样（无 `HREF`、无标题用 URL 顶上、多出的 `</DL>`）、
非 http 协议、回收站、没猜到图标的、slug 退化与去重、~~模板切分（含"域名判不出是不是内网"
这一档）~~（**2026-10-10 随模板删**）、**过不了写路径校验而没能进来的每一条（地址与理由）**、
以及三条对账的逐条结论。**跳过必须记账**——静默丢掉的东西会让报告说
"迁了 N 条"而实际少了 M 条，而丢在哪一行没有任何记录。

真实书签文件**绝不进仓库**（含完整内网拓扑与服务名）。测试夹具一律脱敏；
`flare-sample/` 与真实配置都在 `.gitignore` 里，CLI 守卫（leakguard）会挡住成形地址。


## 10. 部署

多阶段 Dockerfile：`go build` 静态二进制（`CGO_ENABLED=0`；前端模板、CSS 与图标索引全由 `go:embed` 打进二进制）→ `scratch`。非 root 用户。镜像目标 ≤ 20MB。**没有 node 阶段**：图标索引由 `tools/genicons` 生成后作为 gzip 产物提交进仓库（§5），构建期不联网、不装 node。这样本地 `go build`、门禁跑的测试与镜像里的产物是同一份索引，不会出现"CI 绿的形状和镜像里嵌的形状不同"；生成器只在人工刷新图标库时跑一次。

```yaml
services:
  launchbay:
    build: .
    container_name: launchbay
    ports: ["7600:7600"]
    volumes: ["./data:/data"]
    environment:
      LAUNCHBAY_PORT: "7600"
      LAUNCHBAY_WRITE_TOKENS: "ai-dad:${LAUNCHBAY_TOKEN_AI_DAD}:dad,admin:${LAUNCHBAY_TOKEN_ADMIN}:*"
      TZ: Asia/Shanghai
    restart: unless-stopped
    healthcheck: {test: ["CMD", "/launchbay", "healthcheck"], interval: 30s}
```

令牌实际值放 NAS 上 compose 同目录的 `.env`（不进仓库）。没有会话密钥这一项：cookie 不签名（§11）。CLI 子命令在容器内 `docker exec` 运行，读同一 env 里的管理员令牌（§4.5），所以 `LAUNCHBAY_TOKEN_ADMIN` 不只是 AI 在用。

> **2026-10-12 更新，上面那段 YAML 与那句 `.env` 已经不成立了**，照抄会踩空。现状是：
> - compose **只拉已发布的镜像**，`build:` 与 `pull_policy` 都没有了；构建是 CI 的事
>   （`.github/workflows/docker.yml`，推 main 或打 `v*` tag 都发）。所以 `LAUNCHBAY_PULL_POLICY`
>   这个变量不存在，`LAUNCHBAY_TOKEN_AI_DAD` / `LAUNCHBAY_TOKEN_ADMIN` / `LAUNCHBAY_HOST_DATA`
>   也一并没了。
> - 令牌就写在 compose 的 `environment` 里：管理员那把是**独立的一行**

## 11. 安全（按局域网定位明确弱化）

**这一节写清"防什么"和"明写不防什么"，是为了让后面的实现不悄悄长出登录限速、签名 token、权限矩阵这类东西。**

防这些

| 风险 | 为什么必须防 | 做法 |
|---|---|---|
| 真实内网拓扑泄进公开仓库 | 仓库是公开的，泄露不可撤回 | `data/` 与 `.superpowers/` 进 `.gitignore`；夹具脱敏。CI 守卫分两层，**判据写成白名单而不是黑名单**：扫 git 跟踪文件里出现的所有点分四段地址，**唯一允许的私网段是 `10.`（文档与夹具示例段）与回环地址 `127.0.0.1`/`::1`（CLI 按 §4.5 必须只走本机 loopback REST，不算拓扑泄露）**；任何其它 RFC1918 段即红。白名单形状还有个附带好处——本文件不需要写出被禁的地址长什么样，守卫不会扫到自己（黑名单写法在这里必然自咬）。第二层再用 secret `NAS_SUBNET_PREFIX` 精确匹配本家网段兜底；secret 缺失（fork 与普通 PR 本来就取不到）只跳过第二层，第一层照跑，不许因为漏配 secret 就整体静默失效 |
| XSS（书签名/描述里带脚本） | 数据由人和 AI 共同写，注入面真实存在 | `html/template` 自动转义；CSP `script-src 'self'`（无第三方脚本）。CSS 内联要求 `style-src 'unsafe-inline'`，这是省一次 RTT 换来的已知取舍 |
| 写接口把数据写坏 | 三家同时改 + AI 成批改，损坏概率不低 | 原子写、写前快照、ops 整批校验先于落盘、`expectedRev` 冲突拒绝 |
| 服务端被抓图标当探测跳板 | 一个失控的抓取循环能拖慢整台 NAS | 抓取只有一个入口：`/api/v1/resolve`（需凭证，令牌或会话，不收匿名），GET、3 秒超时、页面与图片各 ≤256KB、`image/*`、重定向 ≤3、失败按 origin 记 24 小时冷却、同字节只落一次盘。**没有后台抓取任务**，所以"失控的循环"这一整类失败是被消掉的，不是靠调参数压住的。仍然如实保留一半：任何持凭证者都能让这台机器去访问它自己访问得到的地址（内网段允许，§5.3）——局域网工具的取舍，不是漏洞清单上的新项 |
| 日志泄令牌 | `.env` 之外最容易漂出去的地方 | `history.jsonl` 与状态输出走字段白名单：不记令牌值，不记 ops 内容（可能含 URL） |
| AI 误写别人的档案 | 一次批量写错要逐个档案回滚 | 令牌作用域精确到档案；不符一律 403，不回落 |
| 零档案时被抢装 | 抢到人就是这台盒子的管理员 | 判据（`profiles/` 目录数）与写入同属 store 的一次串行化（§4.5），所以**窗口只开得下一个人**：并发提交里只有一个能成，其余拿到裸 303；建完就关（磁盘上有目录就再不满足判据）；**引导成功不发会话**，进门照样要输 PIN（§8.0）。关的是"有没有目录"这件事，不是"装过机"这个事实：把档案全删掉等于主动把窗口重开，那是重置流程的一部分，不是绕过 |

明写不防（有意为之，实现时不要顺手加回来）

- **不防局域网内冒充。** cookie（今天只有 `lb_profile`）不签名，任何同网段设备改一下就是别人。PIN 因此是方便，不是认证。~~`lb_home` 同样可伪造，但它不参与权限判定（§6.1），伪造它拿不到单 cookie 时代拿不到的任何东西。~~ **2026-10-10 第三轮**：服务端不再发它，读侧只为**拒旧形状**而认它——伪造一条不相等的 `lb_home` 换不到任何权限（整枚会话作废），伪造一条相等的也只是重复 `lb_profile` 已有的那一份。
- 不做爆破防护：无速率限制、无退避、无锁定、无失败计数。
- **不为引导窗口（零档案时那条 `POST /setup`）加安装令牌、二次确认页或速率限制。** 后果明写：装它的人要在场，早到一步的人能当第一个档案的主人（他设自己的 PIN，你只能删档重来）。对策只有三条不另加件的：判据与写入同属一次串行化（所以窗口只开得下一个人，见上表末行）、建完即按目录数关闭、建成也要输 PIN 才进门。删光档案会把窗口重开一次——那是"这台机器回到没装过"的语义，不是漏洞；真要收口就删档案再重装，与"重装也不开"是同一件事的两种说法，这里选说得准的那一种。多出来的防护在这一档局域网定位里也算失败。
- 不做 cookie 签名与密钥轮换，因此也不需要 `LAUNCHBAY_SESSION_SECRET`。
- PIN 用 `sha256$盐$摘要`，不用 argon2/bcrypt：4 位数字本来 1 万种，慢哈希在有口令库的机器上才有意义，而这里的对手不存在。
- 不做 TLS 终结（LAN http）。要真加密就在 NPM 上挂证书，本项目的代码不为这个假设负责。
- 不做"对管理员保密"。§1 已写明；管理员进别人档案的补偿只有横幅 + 历史留名，都是提示而非拦截。
- **不防"管理员凭证能整份重写任何档案的 `profile.json`"（④.6）。** 后果明写：拿到 `*` 令牌或管理员会话就能把某人降为非管理员、把 `theme`/`layout` 重置成默认。对策只有两条不另加件的：读得动就 409（所以这条通路拿不来当改档用）、`admin` 必填（省略不等于 false，静默降级唯一管理员是要紧事）。限流、"改管理员要二次凭证"、"是不是最后一个管理员"的检查都不要——那需要 §4.5 之外的第二份判据，而能建档能删档的凭证本来就能做更少的动作就毁掉这个档案。多出来的防护在这一档局域网定位里也算失败。
- 不做内容安全过滤（成人站点拦截之类）。家长控制是非目标。

## 12. 错误处理

- 写失败一律结构化返回 `{code, detail, opsIndex?}`；前端乐观更新失败**必须回滚 UI** 并显式 toast，不许静默。
- 图标解析失败 → 回退首字母；favicon 抓取失败 → 同样回退首字母，并按 origin 冷却 24 小时（§5），在 `resolve` 里降级成 `favicon: null` 而不是整次失败。缺图**不往 `usage.json` 记**，由 `/api/v1/status` 读时算成 `iconUnmatched`（§5）。界面上看得见（角标"图标未匹配"），不假装成功。
- 某档案 JSON 解析失败 → **只坏那一个档案**：其余照常渲染，该档案页面第一句是人话主句"这个档案的数据文件读不了"，store 给的原文（含文件名与行号）收进 `<details>` 展开可见，`/api/v1/status` 汇总 `brokenProfiles[]`。一个人的手误不该让全家开不了导航页。隔离不把它藏起来：坏档在进门页要点名（§8.0），从前"唯一那份坏了 = 一张卡都没有的空页面"就是这里的死路。隔离**不影响**进门页的档案数判据：`CountProfiles()` 数的是目录，坏档案照样占一个位（§8.0）——否则"把一个档案装坏了"等于把引导窗口重新打开，第二个人可以合法地再建一个管理员。隔离也不把人困住：**唯一被支持的修法是 `POST /api/v1/profiles/rebuild`**（§6.1；只重写 `profile.json`，书签与快照不动），进门页那句"要在这台机器上修好那个文件"指的就是它。手工路线一律算错——尤其"删掉坏文件再建档"：`CreateProfile` 无条件写一份 `bookmarks.json`，会把盘上那份**还能读的**书签一起覆盖掉。`profile.json` 里的 `theme`/`layout`/`createdAt` 读不出来就没有"保留"这个选项，重建按默认值走，这是明写的取舍，不是 bug。
- `?profile=` 指向不存在的档案 → `404`，与"无权限"分开返回。
- 快照目录写失败（磁盘满）→ 拒绝该次写入并报 `507`，**不"跳过快照继续写"**：快照是唯一恢复手段。
- 进程崩溃 → `restart: unless-stopped` 拉起；原子写保证任何时刻 `bookmarks.json` 都是完整文件，不会半截。
- 渲染内存缓存与磁盘不一致（外部程序改了文件）→ 按档案 mtime 失效重算。

**⑥ 的双档案离线端到端回归**（§7.1 与 §14 都引用它，而这里才是它第一次被写下来）。

它要防的是**串号**——§7.1 原话："共用设备上离线残留别人书签算泄露"，而 §7.1 的键表里唯一带档案的一维就是 SW 的 HTML 缓存名。Go 单测碰不到它：缓存住在浏览器的 Cache Storage 里，而"爸爸的设备离线时打开看到的是谁的书签"这件事，只能在**两个档案都在这台机器上、断网、同一台设备**的条件下验出来。四条，每条都要在**浏览器**里做：

1. **两个桶各归各位**：在同一台设备上依次进 dad 与 kid 各自的档案首屏，DevTools → Application → Cache Storage 里必须出现 `html-dad` 与 `html-kid` 两个桶，**每个桶里只有那一个档案的页面**。
2. **离线不打错人**：**停掉服务**（比断网更彻底：连都连不上，这就是离线的样子），此时切到另一个档案刷新 —— 回退出来的必须是**那个档案**的书签。串号就是这一条红：dad 的名字底下出现了 kid 的链接。
3. **切档清旧缓存**：从 dad 切到 kid 之后，`html-dad` 那个桶必须**消失**（§7.1 的"切换档案时清掉上一个档案的 HTML 缓存"）。留着它就等于共用设备上还留着别人的一份。
4. **`-admin` 一律不存**：访问过 `/admin` 之后，Cache Storage 里**不得出现** `html--admin` —— 那一面含全家庭的档案名、条目数、rev 与快照数，比选择页敏感一档。

判据是**看得见的桶与看得见的内容**，不是"页面能打开"：这条回归的价值全在它能看见那三个东西上，只断言"离线时首屏还在"的话，串号照样全绿。

做这一条要**真浏览器 + 一次人工登录**（PIN 框是认证材料，工具不代填），而且要**真的停掉服务**才算离线 —— 用 DevTools 的 Offline 勾选不够，它拦得住 fetch 拦不住已经在飞的那次请求。
- 预算闸：按当前真实规模（25 条）与 200 条余量各一份，量 HTML gzip、内联 CSS、`<script` 计数。
- 三条新路由过既有契约闸（`routes()` ↔ `openapi.json` ↔ `AGENTS.md`；闸的条数由 `internal/httpapi/openapi_test.go` 与 `agents_test.go` 自己说了算，这里不抄数字），不放宽任何一条豁免。
- CI 在干净克隆上跑通（含泄漏守卫），且 CI 的输入文件都在仓库里。

P1-④.5 首次运行与默认单人（进门页三形状 + 两条建档表单）

- 三形状：0 档案的页面里没有「谁来用？」字样、有 `action="/setup"` 的表单；1 档案的 h1 就是那个名字、且**恰好一张** PIN 卡片（不是两卡一排）；≥2 与 ④ 的形状逐字一致（拿现存夹具当基线，改动一排卡要红在这里而不是在验收当天）。
- `/setup` 建成：0 档案 → 合法名字 + PIN → 磁盘上出现该档案，`profile.json` 的 `admin == true`、id 按 §6.1 `/setup` 行说的派生规则来、PIN 哈希形状是 `sha256$盐$摘要`。判据是**回读磁盘**，不是看返回值。
- `/setup` 自己关上门：已有 1 个档案 → POST `/setup` → 303 回 `/` 且 `Location` 不带 `err`，**磁盘逐字节不变**。这一条同时挡"忘了关窗"和"关了但仍写盘"两种错。
- 成功不发会话：那条 303 的 `Set-Cookie` 不含 `lb_profile`。实现里多写一行 `auth.SetSession` 必须当场红——免令牌建档不等于免令牌进入。
- 字段错说人话：缺名字 → `?err=noname`；PIN 三位 → `?err=badpin`；两个键都在 `pinNotices` 表里，未登记的键渲染成空（§6.1 那条白名单纪律的延伸）。
- `POST /admin`：管理员会话建成普通档案（`admin:false`），勾了「能管理全家」才 `admin:true`；非管理员会话、无会话、`*` 令牌三种打法都是 303 且**磁盘不变**（表单通路不认令牌）。勾与不勾的接件值是从模板取的，模板改 value 会同时红"行为"与"形状"两条证人。派生 id 撞上并发提交要说人话：40 个并发同名提交里每一次都必须是 303、`Location` 只有成功与 `?err=nametaken` 两种，管理页得把那句话说出来——少了 409 那一支，它会吐一个"内部错误: \<nil\>"的 500。
- 判据只有一份：`auth.ValidPinFormat`、`auth.HashPIN` 与 store 的建档调用，在建档这一族里只许出现在一处。证人是 `internal/httpapi/createrule_test.go` 的**整包 AST 扫描**（`parser.ParseDir` 取非测试文件、按函数体认落点，刻意不认接收者名、抹掉空白后再比），不是"grep 一下字符串"——照字面去补一条 grep 测试会长出第二个证人。两个壳各自不许再写一遍校验；同一份非法输入分别打两壳，断的是**接受/拒绝的判定一致**——文案形状本来就该不同（JSON 点名字段 vs `?err=` 白名单键），所以不能拿"字符串相同"当证人。
- 窗口只开得下一个人：0 档案时并发发两次 `/setup`（不同 title，各自都能派生出合法 id），磁盘上**只多出一个**档案，另一个拿不带 `err` 的 303。这条测的是 store：把锁内重查改成"handler 先查后写"，它必须红——否则它断的是一个不存在的保证。
- id 派生表驱动：`爸爸` → `home`（中文 slug 不出东西，走基名序列）；`Dad` → `dad`；`nas box` → `nas-box`；`---` → `home`；`home` 已存在 → `home-2`；删掉 `home` 之后新建仍然拿到 `home`（这一条证明判据是"目录在不在"，不是"有几个档案"）。
- 契约面：`/setup` 与 `POST /admin` 过既有契约闸（`routes()` ↔ `openapi.json` ↔ `AGENTS.md`；闸的条数由 `internal/httpapi/openapi_test.go` 与 `agents_test.go` 自己说了算，这里不抄数字），而且 `openapi.json` 的 `security` 与 `x-credential` 两格各自钉回路由表的 Cred——`POST /admin` 拒令牌，它的 `security` 就不许报 `bearerAuth`。`<script` 计数为 0 的名单含引导那一形状；预算读数只在原线内，不抬线。
- 实拍（人在浏览器里，不是断言）：全新空目录起服务 → 建第一个 → 输 PIN 进门 → 顶栏管理 → 建第二个 → 首页变成「谁来用？」两张卡。这一段是本片真正的验收，前面那些都只是必要条件。

P1-④.6 坏档案的机器出路（`profile rebuild`）

- 坏档 rebuild 之后 `profile.json` 读得动，而 `bookmarks.json`、`snapshots/` 下每个文件、`history.jsonl` 的**已有内容**逐字节不变（历史只多一行）。判据是读磁盘的 sha256，不是看返回值。
- 读得动的档案打它 → 409，且**没有发生任何写**（回读一份"没被动过"的档案要用 sha，不是"看起来一样"）。
- 半件事目录（有目录、没有 `profile.json`）→ 允许重建，且目录里只多出一个 `profile.json`。
- 目录根本不存在 → 404，且**不创建任何目录**：这条端点不是第二条建档通路，建档案仍然只有 `POST /api/v1/profiles`。
- `LoadProfile` 报的不是"内容错"而是权限/磁盘那一类 I/O 错 → 原样上报、不覆盖。读不动不等于内容错，那时盘上那份还可能救。
- 写完回读仍读不动 → 500 且坏档登记**留着**；成功 → `/status` 的 `brokenProfiles` 里那条消失。这一条钉的是"响应说成功 = 进门页那张卡真的回来了"，不是"写盘返回了 nil"。
- 端到端（人跑一遍，不是断言）：真起实例 → 写坏唯一档案 → 进门页那句点名 → `launchbay profile rebuild` → 那张卡回来 → 书签内容与坏掉之前逐字节一致。
- 并发：同一档案两路 rebuild、以及 rebuild 与设 PIN（同一把按 id 的锁的另一个用户）交错 → 不产生半写文件，后写的赢且文件永远是能解的 JSON。枪：把 `WithProfileLock` 去掉 → 这条与 `-race` 一起红。本机 `CGO_ENABLED=0` 跑不了 `-race`，那一条在 Linux 容器里补跑（§10 的构建口径），方法账要写进验收文档。
- CLI：`launchbay profile rebuild` 的参数→请求体接线，含一个不能含糊的形状——`--admin` 旗标省略时**显式发 `admin:false`**，不是"省略那一格"（API 侧必填的正是这一点，壳不许替调用方猜）。失败退出码非 0 且把服务端 `detail` 原样说出来；成功打印新档案的 `id`/`title`/`admin`。
- 契约面：`routes()` ↔ `openapi.json` ↔ `AGENTS.md` 三处过既有闸；PIN 的格式与哈希抽成建档族共用的一份之后，"在 rebuild 的壳里自己哈希一遍"必须让 `createrule_test.go` 那道 AST 闸红——这一枪不打，换了口径的闸就是假闸。

契约测试：`openapi.json` 与实际路由逐条对照。文档骗 AI 比骗人更贵——AI 会照着它生成错的请求。

界面：无头 Chrome 真实渲染服务端产物，断言 DOM 形状（分组数、磁贴数、图标是否内联、管理横幅是否存在与否）而非文本匹配。**没有独立的 JS 前端，因此也不设 node 测试层**——测试断言的形状必须和 §10 的产物同源，否则绿的是一回事、跑的是另一回事。

必须真跑的四条关键回归

1. 改一条书签 → 破 HTTP 缓存与本地存储 → 二次打开看到新值。
2. 离线 → 仍能浏览全部书签 → 点添加进待办队列 → 恢复后自动落库并提示。
3. 同一浏览器交替用 A、B 两个档案，各自在线看一次再全离线 → **A 的离线页里没有 B 的条目，反之亦然**。这条是隔离方案唯一的真风险点，必须端到端跑，不能只看单测绿。
4. 图标端到端：在真实夹具档案上跑一轮完整通路——`/api/v1/icons` 搜名 → `POST /api/v1/batch` 写入 → `GET /api/v1/data` 复核 → 首屏断言内联 `<svg>` 条数等于"有条目且名字查得到"的数量、且除缓存 favicon 外零图片请求。它防的是索引、写校验、渲染三段各自绿而接起来不通。

## 15. 开放项

- **档案被删之后，它的 `html-<id>` 缓存桶会留在设备上**（⑥ 的已知边界，2026-10-10 实测记录）。§7.1 要求「切换档案时清掉上一个档案的缓存」，那条**已实现**（页面在 `POST /switch` 提交时 postMessage 给 SW，改写 IndexedDB 的当前档案并清掉上一个桶）；而**档案被删**是另一件事：那个档案再也不会被切进去，所以那条 switch 路径永远不会触发。要清它需要「这台机器现在还有哪些档案」这份清单 —— 只有选择页拿得到，而**选择页是零 JavaScript 的**（§8.1），给它挂脚本只为发一条清单不划算；档案页则只知道它自己是谁。所以要清只有两条路，都还没选：给选择页加一小段 JS 把清单发给 SW，或者接受这个残留（共用设备上删掉一个人的档案后，他的离线副本仍在）。**先记着，不要假装它已经被处理。**
