# 全量代码与文档审计记录 · 2026-11-19

> 色板刷新之后的第二轮见 [audit-2026-11-19-round2.md](audit-2026-11-19-round2.md)。

launchbay 是家庭局域网内的独立档案书签导航台。本次按用户指令做全量审计（逐条检查并更新注释、docs、agents、readme），保持标准库零依赖、现有权限边界与"判据只有一份"的纪律，不改产品的对外契约。

审计覆盖后端 Go 代码、前端脚本与样式、模板、CLI、浏览器扩展、CI/部署文件，以及契约文档（`AGENTS.md`）、机器契约（`internal/httpapi/openapi.json`）与双语主文档（`README.md` / `README.zh.md`）。目标不是把句子写得更漂亮，而是**让每一句仍然在说真话**：端点、字段、默认值、数量与常量、以及"某件事发生在哪一处"。

2. **文档里的名字逐个落地**：把 `AGENTS.md` / 两份 README 里所有反引号标识符与代码语料对了一遍（函数名、字段名、文件名、端点），没有指向不存在的东西。
3. **逐节对读**：按令牌与鉴权、端点表、备份族、CLI、语言、界面交互、`/prefs` 面板、双地址、图标、发版、禁止事项的顺序，把每一段的行为描述与代码现状对读；带日期的历史陈述保留，**现在时的事实**按代码改。
4. **注释审计**：四个只读审计代理分别扫 `internal/httpapi`、`internal/store|model|auth|ops|i18n|bookimport|icons`、`internal/render`（含 JS/CSS/模板）、`cmd/launchbay` + `extension` + `tools` + CI 的注释，逐条给出证据；本记录只收**经过复核**的那些。

## 值得单独说清楚的两处

**一、`revert` 的历史 actor 是行为修正，不只是注释。** 历史页那套判据按"经手人是谁"分：档案 id 一律不显示（本人），令牌名要显示（"家里哪把钥匙"）。`revertLocked` 收了 `actor` 却写 `Profile: id, Actor: id`，于是**令牌触发的回退在历史里永远读成"本人"**；而 batch、设 PIN、停用、重建四条同族通路都写 `Actor: actor`。改为写 `actor` 之后，CLI/AI 用令牌退版本这条路的"谁"才回答得出来。既有测试没有钉过这一格（`revert_test` 不查 Actor），改动由 `internal/httpapi` 全量测试与历史页相关测试共同覆盖。

**二、选择页那张脸换过一次，注释追了两层。** 2026-10-12 的"最常用站点图标"要读整份 `bookmarks.json`，当时连"选择页因此每份档案多一次文件读"的 A/B 读数都写进了注释；2026-10-17 用户改判成首字母色块之后，`faceOf` 不读任何书签，那些"代价/为什么不缓存"的段落反而成了误导（会让人以为今天还有一次文件读）。本轮把这段改成"代价的变迁"，并删掉"这张脸为什么不缓存"——它今天是 `Profile.Title` 的两个纯函数，没有可缓存的对象。

## 未验证的环境

- `LB_UI=1 go test ./tools/uicheck/` 没有在本机跑：它要 node 与一个可用的 Chrome/Edge，且是几分钟级的真浏览器横扫。本轮审计本身没有改界面行为；工作区原有的启动器改动（改用 DevToolsActivePort 取端口、进程组收尾）也只做到了 `go test` 编译通过，没有用真浏览器验证。CI 的 `ui sweep` job 仍是这条闸的常驻执行者。
- 没有执行 `go test -race`（本机无 cgo/可用 C 编译器）与 Docker 镜像构建/起容器测试；竞态与镜像由仓库现有的 Ubuntu CI 负责。
- 没有在真实 NAS、ARM 设备上运行，也没有重新测量局域网 LCP、千条书签滚动帧率等数字；文档里那些带日期的实测读数按原样保留。

审计与测试全程只用临时目录，没有碰真实 `data/`；没有部署。本轮改动按功能域分提交入库：界面闸启动器、回退历史 actor、选择页死字段各一笔，其余文档与注释合成一笔。

工作区在本轮**开始前**已有一组与本审计无关的 `tools/uicheck` 启动器改动（`uicheck_test.go` 的改法 + 新增的 `browser_other_test.go` / `browser_unix_test.go`，主题是调试口改由浏览器自己选端口、进程组收尾）。本轮没有改它的内容，按功能域单独提交；上面的全量测试是在包含这组改动的状态下跑过的。
